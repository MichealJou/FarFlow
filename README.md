# FarFlow 研流

研发协作管理工具，覆盖需求收集、产品规划、研发任务、测试、Bug、版本发布和知识沉淀。

**产品名确定为 FarFlow · 研流，项目目录为 FarFlow。** “研”表示研发，“流”表示从想法到交付的流转。

## 已确定的产品方向

- 同一套代码、同一套业务规则、同一套数据模型。
- 创建工作空间时选择本地、Git、服务三种模式。
- 同一客户端可以打开不同模式的工作空间。
- 本地和 Git 模式无需运行应用服务；服务模式连接可选服务端。
- 三种模式均纳入产品范围，差异集中在存储、同步、身份验证和协作能力。
- 当前已实现共享核心、本地与 Git 适配、评论附件、备份恢复、独立 Bug 复测、远端同步，以及 PostgreSQL 账户、工作空间和业务服务；六条正式交接方向已有库和统一命令行入口。共享界面、macOS 优化桌面包的本地／Git 创建与重开、桌面服务跨端保存，以及 Rust 直接托管网页已有真实运行验证。Git 离线包导出、创建副本及回传导入已通过原生操作验收；优化迁移工具已接续桌面实际数据并保留评论与附件。本地与 Git 的桌面正式迁移向导已完成连续往返、评论续写和冷启动读取验收；服务远端向导、后台选择器焦点边界、性能、跨平台分发及最终比对尚未完成，不能作为正式版交付。进度以 [交付矩阵](docs/05-交付进度.md) 为准。

## 当前代码验证

在项目目录执行：

```sh
npm run typecheck
npm run test:coverage
npm run build
cargo test --workspace --offline
cargo clippy --workspace --all-targets --offline -- -D warnings
cargo llvm-cov --workspace --offline --fail-under-lines 80 --fail-under-functions 80 --fail-under-regions 80
npm run desktop:build
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml --offline
```

核心与本地存储位于 `crates/core`，原生会话适配位于 `crates/desktop`。SQLite 不启动 HTTP 服务，附件按 SHA-256 保存，数据库事务同时更新业务投影与操作日志。账户服务位于 `crates/server`，可用 `cargo run -p farflow-server --offline -- --help` 查看运行方式；设置 `FARFLOW_WEB_DIR` 后同时提供优化网页。全套测试需要可用的 Git、Python 3、PostgreSQL `initdb` 和 `pg_ctl`；数据库测试只使用自行创建的临时数据目录。命令测试与实际界面验收分别记录。Tauri 壳独立测试，不能遗漏或把根工作区测试当成壳测试。覆盖率原始报告、原始测试日志、运行数据和构建产物仅留本机，不进入代码仓库；验证说明与摘要保留，原始报告可按文档命令重生成。
