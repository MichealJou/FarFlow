# 服务备份与恢复

代码位于 `crates/server/src/backup.rs`、`storage.rs`。本功能保存完整服务的账户、账户历史、登录限制、全部工作空间、原始操作、业务状态和实际附件。不是单个工作空间 JSON 导出，也不是数据库服务器角色、扩展和配置的备份。

## 数据库与目录绑定

`ff_storage` 保存存储身份、规范路径摘要及就绪状态；数据目录的私有 `storage.json` 保存相同身份。启动时核对两者。相同规范目录可重复启动，明确配置的目录链接会先解析成规范路径。已经就绪的数据库不能直接换附件目录；复制到另一位置的目录也不能直接配原数据库使用。需要搬迁时，使用下面的完整备份恢复。

首次创建先提交待初始化身份，再原子落位标记，最后标记就绪。同一目录初始化中断可重试；已经就绪后标记丢失、损坏或不匹配时拒绝启动，不静默重建空目录。工作空间请求也检查标记。已有账户或空间、但没有绑定记录的早期试验库会拒绝自动接管；这类旧格式的升级仍待实现，不会被覆盖。

## 备份

运行前设置源数据库的 `DATABASE_URL` 和 `FARFLOW_DATA_DIR`。使用当前已改密、启用的服务管理员会话，通过环境变量设置 `FARFLOW_BACKUP_TOKEN`，不把令牌写入命令参数、项目文件或 Git。

```sh
cargo run -p farflow-server --offline -- backup /独立保存位置/新备份目录
```

目标父目录必须存在，备份目录必须尚不存在，而且位于服务数据目录之外。成功后输出备份 ID；不会输出数据库连接、口令哈希或会话令牌。完成后从当前环境移除 `FARFLOW_BACKUP_TOKEN`。

备份使用 PostgreSQL 的 Repeatable Read 事务取得一致快照，再按快照复制不可变附件。该隔离级别为事务中后续查询保留同一快照，依据 [PostgreSQL 事务隔离文档](https://www.postgresql.org/docs/16/transaction-iso.html)。账户管理在导出期间受共享身份锁保护，普通业务命令和上传可继续；当前没有附件物理回收，故旧快照引用的字节仍在。若后续实现物理回收，必须继续保护备份所需文件。

| 内容 | 包内位置 |
| --- | --- |
| 清单、格式、备份 ID、源存储 ID、时间、文件大小及 SHA-256 | `backup.json`，最后写入 |
| 账户资料、权限、停用与初次改密状态、原口令哈希 | `accounts.jsonl` |
| 账户操作历史及公开资料前后快照 | `account-events.jsonl` |
| 登录失败窗口和暂时限流状态 | `login-attempts.jsonl` |
| 工作空间原始初始状态、投影、修订号、校验值、身份绑定和可选的完整复制来源 | `workspaces/空间ID/workspace.json` |
| 可选迁移控制、完成凭据及有序阶段事件与实际账户 | 同一 `workspace.json` 的 `transfer`、`transfer_events` |
| 客户端请求、真实操作者请求、回执、修订号 | `workspaces/空间ID/operations.jsonl` |
| 实际附件，含已移除引用或归档对象的历史字节 | `workspaces/空间ID/attachments/哈希前两位/哈希` |

账户和历史分页读取；操作日志使用 JSONL 逐行保存，恢复逐行写入，不把整个服务的所有空间状态合并成一个大 JSON。业务初始状态及请求继续保留 TEXT 原文，包括负零、换行和制表符。复制空间同时核对完整来源图和原始客户端请求，保留放弃分支的历史附件；空间成员索引由已验证的最终成员及真实账户绑定重新生成。详见 [服务身份映射与三模式复制](14-服务身份映射与三模式复制.md)。

备份包含口令哈希和业务附件，属于私有数据。Unix 新建备份目录为 `0700`，元数据文件为 `0600`；附件继续复用核心私有原子写入。SHA-256 用于完整性检查，不等于加密或可信来源认证。文件系统权限和私有临时目录不能替代备份介质本身的访问管理。

## 恢复与搬迁

先为目标准备独立空数据库和独立数据目录，并将 `DATABASE_URL`、`FARFLOW_DATA_DIR` 指向它们，再执行：

```sh
cargo run -p farflow-server --offline -- restore /独立保存位置/备份目录
```

恢复不需要源服务在线。源备份先复制到私有临时目录，验证路径、文件类型、数量、大小及哈希；不允许符号链接或额外文件。再校验账户和密码参数、账户历史、登录限制、初始状态、每条操作与回执、最终投影、有效所有者及全部附件。工作空间会通过共享核心完整重放，不仅比较文件哈希。清单与历史不符时，在触碰目标恢复状态之前拒绝。

随后只向已知表执行参数化写入，不解释或执行包内 SQL。已有业务账户、工作空间或无关附件目录会被拒绝。业务 ID、版本、角色、停用状态、强制改密状态和密码哈希保持；目标存储身份与路径单独建立。所有原会话均不备份、不恢复，恢复后必须重新登录，避免已撤销会话随旧备份复活。

恢复先持久化 `ff_restore` 中的备份指纹及未完成状态，再安装不可变附件。最后在一个事务中恢复全部业务表并标记完成。数据库失败会回滚账户、业务、日志及索引；可能已落位的附件保留，供重试核对复用，不冒充已完成恢复。中断后正常启动和管理员初始化被拒绝，应使用**原备份、原目标数据库和原目录**重试同一命令。不能改用另一备份混合恢复。相同恢复已完成后再执行，会报告已完成且不改动现有数据。

恢复保留冻结、暂存、完成、激活及取消阶段，不会把只读迁移空间自动开放写入；核对时重建完整历史并检查事件账户绑定。具体规则见 [服务正式迁移与账户交接](16-服务正式迁移与账户交接.md)。

恢复成功后：

```sh
cargo run -p farflow-server --offline -- serve
```

重新登录后检查空间、成员、发布快照、历史和附件，再继续协作。若需要另一时间点，使用新的空数据库与独立目录恢复，不覆盖当前服务。

## 当前边界

现有功能为库级接口和可执行命令：`Server::backup`、`Server::restore`。管理员备份界面、受控下载、计划备份、加密归档、远程介质和保留策略尚未接入。没有允许客户端任意指定服务端文件路径的 HTTP 接口。

目前限制清单最多 100000 文件、单条 JSONL 最多 16 MiB、单个空间元数据最多 512 MiB；附件仍为单文件 10 MiB。密码哈希仅接受当前服务生成的 Argon2id 参数。此处是协议和资源边界，不是已证明的性能容量。现有完整空间投影和重放仍需按 1 万工作项、5 万操作的计划测量，未宣称大规模恢复耗时达标。旧试验格式升级、三模式迁移、孤立文件回收、断电演练和目标平台验收仍需继续完成。

验证见 [服务备份记录](验证记录/2026-10-25-服务备份与目录绑定.md)，整体范围见 [交付矩阵](05-交付进度.md)。
