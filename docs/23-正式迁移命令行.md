# 正式迁移命令行

`farflow-migrate` 已接入本地、Git、服务之间六个正式迁移方向。工具复用现有迁移库，保留原工作空间 ID、业务 ID、历史、成员及实际附件；不会把正式迁移当成普通复制，也不会跳过冻结、暂存、源完成和目标激活。

## 构建与运行

```sh
cargo build --release -p farflow-server --bin farflow-migrate --offline
target/release/farflow-migrate --help
```

该工具独立于桌面安装包，本地与 Git 命令不读取服务环境变量、不启动数据库或 HTTP 服务。服务命令在能够访问实际 PostgreSQL 和服务数据目录的管理机器上运行，需要明确设置 `DATABASE_URL`、`FARFLOW_DATA_DIR`、`FARFLOW_SESSION_TOKEN`。会话必须属于当前启用、已完成改密且具有对应空间所有者身份的真实账户。配置与会话从本机安全来源注入，命令参数不接受密码或会话令牌。

新增二进制没有改变原服务的默认入口，`cargo run -p farflow-server -- serve` 仍运行服务。此次没有新增第三方依赖，沿用工作区现有的核心、服务、Serde、Tokio、SHA-256 和 tempfile。

## 标识与身份

| 命令 | 用途 |
| --- | --- |
| `new-id` | 输出一个新的迁移 UUID |
| `local identities <空间目录>` | 列出原空间、全部成员 UUID、角色和启用状态 |
| `git identities <空间目录>` | 列出 Git 空间与原有成员，不自动取得所有者身份 |
| `inspect <交换包目录>` | 校验交换包，返回原空间、完整历史身份集合、计数和迁移计划 |

本地和 Git 的成员查询沿用系统文件权限边界，之后每项迁移动作仍需明确指定实际成员并执行原权限校验。服务空间 UUID 可从现有空间列表 API 读取，账户 UUID 来自已有用户管理及 `GET /api/users`；该账户接口仍要求服务管理员。身份映射必须覆盖交换包报告中的全部历史成员，一对一对应真实账户，不能只映射当前启用成员。

## 空间阶段操作

本地与 Git 使用：

```text
farflow-migrate local|git <操作> <空间目录> <实际成员UUID> [操作参数]
```

服务使用：

```text
farflow-migrate service <操作> <空间UUID> [操作参数]
```

| 操作及参数 | 行为 |
| --- | --- |
| `status` | 查询当前源或目标阶段，不返回完成令牌 |
| `events` | 本地与服务返回阶段事件；Git 返回全部源计划、所需成员、确认集合和迟到业务标记 |
| `prepare <迁移UUID> <目标模式> <新备份目录>` | 先保存备份再冻结，拒绝源和目标模式相同 |
| `export <新交换包目录>` | 导出固定切点；同一有效包可重试；Git 源需已收齐停写确认 |
| `complete <回执JSON文件> <凭据JSON文件>` | 核对目标回执，确认源永久只读，将完成凭据写入文件 |
| `activate <凭据JSON文件>` | 目标核对源完成凭据后开放写入；相同凭据可重试 |
| `cancel <迁移UUID>` | 仅在源完成前取消；源完成后拒绝取消 |

准备时的备份仍遵循各模式原有协议。服务单空间备份不能代替管理员的完整账户及服务灾备。

## 目标暂存

```text
farflow-migrate local stage <交换包目录> <目标空间目录> <实际所有者UUID> <回执JSON文件>
farflow-migrate git stage <交换包目录> <目标空间目录> <实际所有者UUID> <回执JSON文件>
farflow-migrate service stage <交换包目录> <身份映射JSON文件> <回执JSON文件>
```

本地与 Git 的目标目录必须独立于交换包。服务映射文件是“历史成员 UUID → 真实服务账户 UUID”的 JSON 对象，读取上限 16 MiB。服务当前会话对应映射后的启用所有者；服务管理员不能借管理员身份绕过空间所有者校验。

成功暂存只建立只读目标。工具返回核对报告及回执文件位置，随后由源端 `complete`，最后在目标执行 `activate`。重复暂存同一包与计划会核对原目标，保留目标激活后新增的评论或业务，不用旧切点覆盖。

## Git 停写声明及发起副本恢复

```text
farflow-migrate git acknowledge <空间目录> <实际成员UUID> <迁移UUID> <说明UTF-8文件> --all-copies-stopped
farflow-migrate git restore-origin <私有恢复目录> <目标空间目录> <实际所有者UUID> --source-offline
```

第一项表示该成员明确确认：本人名下全部副本已经同步并停止写入。每位启用的可写成员分别操作，查看者和停用成员不代替确认；缺少声明标记、空说明或非 UTF-8 内容会拒绝。程序不会自动替其他成员确认，也不能远程锁住未知离线设备。

恢复原发起副本前必须核对原实例已离线，且没有在另一处取消或完成该计划。恢复保留原设备及冻结控制，不直接开放写入。此声明不代表工具已盘点并锁住所有物理设备。

## 文件、失败与重试

回执与完成凭据必须保存在业务目录之外；服务端还要求位于整个服务数据目录之外。工具先检查父目录及已有文件，已知不匹配的回执或凭据会在改变迁移阶段之前拒绝。临时文件在同一目录写入并持久化，再禁止覆盖地落位；新文件在 Unix 上为 `0600`。已有内容完全相同时可重试，不改写文件，不覆盖不同内容，也拒绝文件符号链接。回执和凭据 JSON 读取上限为 1 MiB。

控制台输出公开报告、阶段、文件路径和错误，不输出完成令牌、会话或数据库连接。完成凭据文件包含专用于单个计划的令牌，不应进入业务 Git 或公开日志。

文件检查后仍可能发生磁盘、目录或并发落位错误。若目标已暂存而回执保存失败，目标继续只读，可用同一包和映射重试到新文件。若源已确认完成而凭据保存失败，源保持只读，应使用同一回执重取凭据。错误不会自动取消迁移，也不会自动恢复旧源写入。

## 当前验证边界

- 六个方向均由实际 CLI 子进程执行，覆盖备份冻结、取消、重新准备、暂存、源完成、目标激活、状态及事件查询。核对原业务 ID、评论、附件字节、三位实际成员与真实服务身份映射。
- Git 源在收齐两位可写成员的本人声明前拒绝导出；私有发起副本恢复、非 UTF-8 声明拒绝及完成后取消拒绝已验证。
- 已知错误回执与凭据在阶段变更前拒绝；目标续写后重试原暂存，新增评论继续保留；所有已完成源继续拒绝业务写入。
- 原生桌面新建的 SQLite 文档、评论与中文附件，已通过优化工具连续完成本地 → Git → 本地交接。交接后完整业务状态一致，桌面重开选择原成员后可读取、预览附件并保存新评论。
- 原生验收曾复现同进程后续目录选择时确认按钮禁用，重启后可以打开；该问题尚未定位修复。迁移后的上述重开采用了重启。随后独立空间同进程重复目录选择、取消附件选择、实际上传和再次重开均成功；该对照不能算作偶发问题已经修复。
