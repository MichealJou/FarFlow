# 本地目标接收与离线接续

正式迁移已接入服务源 → 本地目标，保留同一工作空间 ID、业务 ID、完整历史、原始请求、历史成员和实际附件。加上本地 → Git、服务 → Git、本地 → 服务及[Git → 本地／服务](18-Git源交接与冻结确认.md)，六条不同模式的正式交接方向均有实现。普通复制继续创建新空间 ID，客户端向导及完整桌面应用仍待完成。

## 交接步骤

1. 服务所有者用真实会话核对成员状态，创建独立备份后冻结源。
2. 导出固定历史切点和附件的正式交换包，目标模式必须是本地。
3. 本地所有者暂存交换包，检查空间、历史、附件和报告，取得核对回执。此时本地目标只读。
4. 服务所有者核对回执并确认源已完成交接。服务事务提交后才返回同计划完成凭据，原空间保持只读。
5. 本地所有者激活目标，核对计划、凭据和时间；数据库事务提交后才允许写入。
6. 核对本地业务与附件后使用本地空间。服务进程停止后，本地模式仍可继续评论、读取附件及备份恢复。

如果源尚未完成，可以取消源计划。取消恢复当前源写入，已经暂存的本地目标继续只读。后续迁移必须使用新计划；另一计划的完成凭据不能激活旧目标。

## 本地库接口

| 接口 | 行为 |
| --- | --- |
| `LocalWorkspace::stage_transfer(source, destination, actor, at)` | 校验正式包、目标模式、历史所有者和时间；保存完整历史及字节，安装只读控制和事件；返回本地空间、核对报告和回执 |
| `LocalWorkspace::activate_transfer(actor, at, activation)` | 当前所有者核对目标阶段、计划指纹、完成令牌和时间；在同一 SQLite 事务中更新控制与事件 |
| `LocalWorkspace::transfer_status`、`transfer_events` | 已有接口读取当前阶段及所有者可见的阶段记录，不暴露控制令牌 |
| `LocalWorkspace::backup`、`restore` | 已有完整备份同时保存本地迁移控制、事件、来源与附件；暂存恢复后仍只读，激活恢复后可继续业务 |

库级管理能力已接入[统一正式迁移 CLI](23-正式迁移命令行.md)，六方向真实进程与桌面 SQLite 数据接续已验证；本地／Git 桌面迁移向导已接入并完成原生连续往返，服务远端向导仍待完成。服务业务的真实 HTTP 验证、迁移命令行和原生数据重开分别记录。没有新增允许远端用户随意指定服务器文件路径的接口。

## 数据存储与只读屏障

普通复制和正式暂存复用同一历史安装流程。先在私有临时目录创建 SQLite 空间，保存来源图及原始回执，按真实历史生成投影并校验附件。业务数据、格式 3 控制、阶段事件及 15 条数据库屏障在安装事务内完成，重新打开核对后才把目录放到目标位置。

暂存阶段拒绝业务命令、旧请求重试、附件写入、普通复制导出及发起另一正式迁移；读取和完整备份仍允许。数据库触发器限制五张业务表的新增、更新和删除，其他已打开连接同样受当前控制约束。

激活时先验证当前控制、完整历史、全部事件及操作者，再改变控制和事件。控制写入、事件写入或提交失败时全部回滚，不会只开放业务却丢失激活记录。阶段查询、冷启动和完整备份也会检查过去事件的历史所有者、切点、模式和时间，不能只让最后一条记录正确。

正式包不能通过普通复制入口变成可写目标；目标模式不匹配、普通复制包、无效操作者、早于计划的时间、损坏附件、占用文件、符号链接和源内目录均拒绝。已经存在的不同空间或计划不能被覆盖。

## 重试与权限

同一目标重复暂存会核对原计划与当前所有者，不重新安装或覆盖业务。目标已激活并产生新操作后，重试仍保留新操作、附件与事件。重复合法激活返回原阶段，不重复记录事件。

来源回执继续保留：原始请求可按原结果重试，不能复用冲突提案或决策的 ID 冒充新业务。服务客户端的原始请求记录与历史身份也保留在迁移来源中，不改写成新的本地用户。

本地与 Git 使用可信成员身份，服务登录账户、密码和会话不会迁到本地。进入本地后，权限来自空间成员；服务账户之后的停用不能即时撤销离线本地身份。服务源冻结后的全局停用核对仍按[服务交接协议](16-服务正式迁移与账户交接.md)执行。实际向导还需清楚提示此权限边界。

目标所有者之后可以正常交接角色、停用原成员；过去合法阶段记录保留原操作者。原操作者失去当前权限后，不能凭旧包重新暂存覆盖现有目标。已经激活的本地空间可作为下一次迁移的源，使用新计划和已有备份／冻结流程；以前使用过的计划 ID 不能重用。

## 恢复与边界

本地附件按哈希保存，交换包、备份和恢复均核对实际字节。已发布快照保留原范围，交接后的新评论不能改写原发布结果。

本协议约束受控源与受控目标；单机文件所有者可以复制目录或恢复旧备份，因此不能据此声称存在跨独立副本的全局锁。恢复之前必须确认原实例离线、没有另一处正在写入或执行相反交接。完成凭据是计划专用令牌，完整性校验不是来源系统的数字签名；输入包及本机目录遵守已有可信协作边界。

验证见[本地目标接收记录](验证记录/2026-10-25-本地目标接收.md)，其余交付范围见[交付矩阵](05-交付进度.md)。
