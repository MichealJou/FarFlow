# 桌面 Git 同步

Git 空间现在使用共享界面的“Git 同步”入口，提供获取合并、仅上传、获取后上传三种操作。当前界面不把上传成功当成业务冲突已解决；冲突处理和本机索引重建已有独立入口。未完成决策前，业务写入保持只读。

## 会话与后台任务

`crates/desktop` 的 `GitSession` 固定打开的空间和实际操作者；执行远端操作前重新核对目录身份和成员权限。只读成员可以获取远端记录，不能上传或执行完整同步。目录被替换后，已准备的会话也会拒绝访问网络。

原生入口先验证会话并注册任务，再启动后台线程，返回任务 ID。任务状态和取消入口同时绑定空间句柄与任务 ID，其他句柄不能读取或取消该任务。同一打开句柄最多运行一项远端操作；完成后保留最新结果，关闭空间时取消并清理。注册、关闭与会话验证按同一把短期状态锁排序，网络等待不持有业务会话锁。

共享客户端只在 Git 模式提供这些入口，服务和本地空间不会得到 Git 能力。界面使用状态轮询，切换到文档等业务页面时任务仍在运行；回到同步页保留结果。状态读取失败时保留取消和重读入口，组件卸载会清理轮询。

## 取消与退出

手动取消后等待底层传输结束，界面才恢复开始按钮。本机已保存的操作和提交继续保留；远端结果不确定时提示重试核对。网络阶段共用截止时间，已经进行的本机校验及原子写入不会被当作可回滚网络请求强行中断。

普通 Tauri 退出请求先取消传输并等候任务结束。macOS 的系统退出还单独观察 AppKit 终止通知，因为系统 Cmd+Q 路径不保证触发 `ExitRequested`。通知只等待不依赖界面主线程的后台工作。该桥接复用已有 `block2`、`objc2-foundation` 和 `objc2-app-kit` 依赖；没有新增常驻进程或业务服务。

强制杀进程、断电和系统崩溃不属于正常退出通知；本机数据继续依靠原有事务、不可变操作及重开恢复保护。

## 当前真实操作边界

macOS arm64 优化包已实际验证：从原 Git 空间上传到独立本机裸远端，界面提交号与远端 `main` 一致；用系统 Git 克隆第二副本，在原生界面保存新文档并仅上传，再由第一个副本通过原生界面仅获取，读到同一文档 ID 和正文。普通克隆打开问题已在代码中修复，没有用手工补目录代替产品行为。

故意无响应的本机 HTTP 端点已确认收到桌面请求。等待时仍能切换页面、打开业务文档，再返回同步页取消；端点随后确认连接释放。本轮还暴露了 macOS 系统退出绕过退出请求的问题，补上原生终止通知后，用新端点实际按 Cmd+Q 复测：连接以 EOF 释放，应用及本次 Git 进程均已结束。失败那次端点最终超时，未算作退出通过。

网络取消和进程树清理由单测及真实网络测试分别覆盖；原生通知使用实际等待中的临时 Git 上传任务验证。以上不代表 SSH、HTTPS 托管服务、Windows 或 Linux 已验收。

决策历史浏览已接入，更多连接配置、规模与其他平台仍待完成。当前不能宣称完整 Git 模式交付完成。

## 冲突比较、决策与索引重建

比较接口在同一仓库锁内返回当前已生效状态、待处理问题、原始提案及完整记录集合的 SHA-256 指纹。提案显示实际成员、时间、设备、关联问题和原始内容。当前界面支持明确勾选问题后不采纳所选提案、采用某条原始操作，或复用工作项表单编辑合并内容；所有选择均须填写处理说明并确认，准备合并稿不会写入业务。完整原始字段保留在折叠区域。

桌面决策使用已选择的实际成员，界面不能传入其他操作者。只有所有者或项目经理可决策，替代命令仍经过共享业务权限、版本和状态规则。提交时在仓库锁内核对原文指纹；即使其他决策没有改变业务修订，也会拒绝旧页面的新决策。完全相同的已保存请求可幂等重试，不能借重试改写内容。只处理被明确勾选的问题，其他并发提案和后续受阻记录继续保留。

本机索引重建复用核心现有入口，由完整记录生成派生索引，不改写原始操作。只读成员可以查看提案及重建本机索引，不能保存决策。交接冻结时继续展示记录，拒绝写入。同步运行期间界面暂时停用比较和决策按钮；外部副本引入的新记录仍由指纹校验拦截。

## 从远端克隆

Git 初始化增加“新建空间／从远端克隆”切换。克隆先通过原生目录选择器授权父目录，填写新文件夹与仓库地址，再复用已有受控传输和完整仓库校验；网络工作不持有业务会话锁。同一目录授权最多运行一个任务，任务的读取、取消、关闭和打开均核对该授权，不能从另一空间的同步入口操作克隆任务。

任务完成只表示本机副本已保存。确认完成后才注册打开会话，随后仍需明确选择原有成员；不会创建新成员或默认使用初始所有者。打开前再次校验空间身份，拒绝目录替换。离开克隆界面会取消传输并清理任务；若副本已经完成，文件继续保留，可通过“打开已有空间”检查。状态读取失败保留取消与重读入口，卸载后不处理晚到状态，晚到的打开会话会关闭。

macOS 原生验收已完成：真实本机远端克隆后显示成员选择；以原有只读成员打开两条文档，原正文和内容版本保持，未出现写入入口。再次克隆同一目录被明确拒绝，九个业务文件摘要完全相同。挂起 HTTP 端点下点击取消后连接以 EOF 释放，没有半成品目标目录；克隆等待中实际按 Cmd+Q 后，连接与本次 Git 进程均已释放。以上不等于外部 SSH／HTTPS 托管或 Windows／Linux 运行验收。

## 目录落位不覆盖

新增测试复现了普通目录重命名可能替换后来出现的空目录；这与“已有目录不覆盖”的要求不一致。现在 macOS 和 Linux 直接复用已有依赖树中的 `rustix` 1.1.5，使用带 `NOREPLACE` 的原子重命名；Windows 使用已有 `windows-sys` 0.61.2 的 `MoveFileExW`，不设置替换标记。两者改为直接依赖是因为标准库没有提供同一项禁止覆盖的选项，未手写系统绑定或引入常驻服务。此处也保护调用同一落位步骤的复制、迁移和恢复。

接口依据：[Rust 标准库重命名说明](https://doc.rust-lang.org/std/fs/fn.rename.html)、[微软 MoveFileExW 说明](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)；rustix 的 macOS `NOREPLACE` 到 `RENAME_EXCL` 映射已核对本机正式依赖源码。macOS 测试已验证空目录、非空目录、文件均不被替换，以及新目标成功落位；Windows、Linux 系统调用尚未在本轮实机运行。

## 完整决策历史
