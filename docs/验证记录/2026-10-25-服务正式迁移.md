## 六项服务专项

测试位于 `crates/server/tests/cases/migration.rs`，复用已有真实账户、源包、附件及 HTTP 路由测试能力：

1. `service_source_freezes_old_transactions_and_hands_the_same_history_to_git`：服务源含导入历史、实际服务评论及附件。冻结后新命令和旧请求重试拒绝；固定包与同 ID Git 目标完整状态相等。四张表的 INSERT、UPDATE、DELETE 均实际返回 PostgreSQL `55000`，跨空间移动也被拒绝；冻结前的可重复读事务插入操作返回 `40001`。冻结及完成状态经过完整服务备份恢复仍只读。合法凭据激活 Git 后可继续评论，历史字节一致。
2. `local_source_stages_into_real_mapped_service_accounts_and_restores_active_control`：本地源冻结后，以完全不同的服务账户 ID 显式映射。管理员仅为查看者时不能暂存或激活；映射所有者才可完成目标动作。暂存备份恢复仍不可写；激活后真实会话续写的历史操作者仍是原始成员 ID。重复暂存不覆盖后续操作，激活备份恢复保留状态及附件，后续新迁移取消后可继续写。
3. `native_service_transfer_cancellation_reconnects_and_defers_no_partial_freeze_or_completion`：原生服务空间通过延迟外键使冻结最终提交失败，检查无控制和事件残留、业务可继续。再次冻结后冷重连成功；注入事件写失败时完成回滚。取消恢复业务，旧目标仍暂存；过去计划 ID 在后续计划结束后也不能重用。取消状态可备份恢复。
4. `service_transfer_rejects_bad_sessions_barriers_control_and_actor_audit`：无效令牌、错误头、初始密码、无绑定、非所有者、无效计划和错误阶段均拒绝。屏障被禁用或控制指纹损坏时失败；实际账户与历史操作者不符时事件及备份失败。删除控制但保留事件后，读取和直接 SQL 写入也被拒绝。
5. `service_global_suspension_during_freeze_requires_a_new_explicit_member_cutpoint`：冻结后全局停用成员，原计划无法继续导出或首次完成。取消后明确停用空间身份，再用新 ID 取得切点；新 Git 目标保留该停用状态，旧成员不能重新获得读取权限。
6. `completed_read_only_source_does_not_trap_the_last_owner_account_forever`：普通使用中及冻结中的最后所有者不能停用；确认完成交接后，原账户可停用且旧会话失效。系统管理员仍无自动业务访问权限，退役源的完整备份恢复及再次备份成功，直接写入继续被数据库拒绝。原有最后管理员保护测试全部回归通过。

## 真实 HTTP 完整流程

`workspaces::full_delivery_runs_through_service_roles_and_replays_from_postgres_after_reconnect` 继续使用独立服务进程、实际 TCP HTTP 和 PostgreSQL，完成需求、开发任务、测试失败、Bug 修复与独立复测、产品验收及发布；重启和原始日志重放、完整服务恢复、三模式普通复制也继续通过。

本轮再将原服务的完整已发布空间冻结并正式交给 Git，比较所有核心规范文本及附件；真实 HTTP 向被冻结旧源提交评论返回冲突，Git 激活后可继续评论。另一条链路将已有本地完整状态正式暂存到正在运行的服务，真实 HTTP 可见暂存阶段；激活前后保留相同空间和业务 ID，激活后通过真实 HTTP 继续评论，已发布快照不变。

库级迁移动作、真实数据库屏障和真实 HTTP 业务分别记录；没有把它们当成桌面点击验收。没有创建允许远端用户随意指定服务端文件路径的接口。
