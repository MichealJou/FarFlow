## 新增接口及关键证据

| 接口或业务 | 实际测试 |
| --- | --- |
| `from_remote`、`pull`、`push`、`sync` | 空远端、双副本交换与附件、错误工作空间、角色、内嵌令牌拒绝、本机 URL 编码路径 |
| `GitPush`、`GitSync`、`GitPushFailure` | 结果序列化、非快进、认证、传输、远端策略拒绝、失败保留本机提交 |
| 系统 Git 认证 | 真实 HTTP Basic；无助手失败、仓库助手成功、新副本使用临时系统助手配置；未修改用户全局配置 |
| 真实传输 | Git TCP 端点同步和创建副本，停掉端点后明确失败并保留本机数据 |
| 远端竞争 | 接收期间推进远端后重新获取合并；持续竞争时两轮后停止，保留本机数据 |
| 上传期间继续工作 | 阻塞接收期间仍能保存；返回待同步标记，远端不含这次稍后保存的记录 |
| 超大单次操作 | 50 条各含 50,000 字符的批次在文件落盘前拒绝，已有状态和重开不变，之后正常保存成功 |
| 不可变历史 | 修改或删除已提交操作后，即使最新树可形成合法业务，文件包和首次远端副本仍拒绝导入 |
| `RetestBug` | 通过关闭、失败重开、阻塞待复测、每次记录、处理依据快照、幂等、旧版本冲突、角色、说明和禁止伪造 |
| 回归证据 | 原用例、实际修复构建、提交解决之后的最新执行；拒绝旧通过、其他用例、错误结果及再次解决前的执行 |
| 非修复方案 | 原设计等处理依据确认，拒绝附带伪造修复构建或执行 |
| Git 复测并发 | 独立优先级变化可合并；相反结论保留双方并要求明确决策，冷重放结果一致 |

`complete_delivery_flow_survives_a_real_repository_and_bundle_roundtrip` 贯穿需求收集、评审、开发、测试失败转 Bug、修复、实际回归执行、复测关闭、需求验收、发布和改版。真实仓库重开、文件包恢复后，再上传到真实本机裸远端并从远端创建新副本，逐次比较完整业务状态一致。

网络测试通过管理其实际子进程关闭端点，不把进程启动器退出当成端点退出。Python HTTP 夹具仅用于测试，产品代码仍委托系统 Git。
