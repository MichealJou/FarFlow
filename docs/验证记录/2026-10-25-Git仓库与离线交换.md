## 公开接口测试映射

| 接口或类型 | 直接验证 |
| --- | --- |
| `GitWorkspace::create`、`open`、`info` | 仓库保存重开测试；模式、名称、独立目录、设备身份、格式和既有目标保护 |
| `snapshot` | 缓存丢失及损坏、成员停用、并发写入、已提交操作篡改、恢复记录与权限测试 |
| `execute` | 幂等、真实操作文件、双句柄旧版本冲突、角色、缺失附件元信息和完整业务流程 |
| `upload`、`read_attachment` | 实际字节、哈希、去重、墓碑、失败不留操作、冲突提案双方附件的文件包往返 |
| `resolve` | 双真实仓库正文冲突，明确决策以新文件保存，重复决策幂等，重开后结果一致 |
| `rebuild_index` | 删除索引、损坏数据库、无效缓存 JSON 和索引写入触发器失败后的恢复 |
| `merge_from` | 两真实仓库双向合并、重复合并、不同工作空间、缺失依赖、导入中断和坏恢复记录 |
| `commit` | Git 实际提交、无变化不新增提交、双方祖先保留、权限及空说明拒绝、钩子和内容过滤器不执行 |
| `export_pack` | Git bundle 实际生成、导出权限、既有文件保护、排除本机 SQLite 和设备身份 |
| `import_pack` | 真实包导入、重复导入、业务已落位但 Git 关联失败的提示和重试、坏包及意外路径拒绝 |
| `from_pack` | 从文件包创建新副本、新设备身份、业务重开、初始所有者停用后的副本、既有目录保护 |
| `GitSave` | 索引成功及失败状态，序列化往返保留原业务回执 |

## 关键实际结果

`two_real_repositories_exchange_independent_changes_and_attachments` 建立两个独立 Git 数据仓库，各自离线新增业务并上传真实附件，双向导入后比较完整投影，业务和附件均存在，重复导入保持不变。

`offline_bundle_import_preserves_business_data_and_both_git_ancestors` 在两个仓库产生各自的 Git 提交，通过 `.farflowpack` 交换后，实际调用 `git merge-base --is-ancestor` 证明双方提交都成为合并后提交的祖先；重复包不增加业务或无意义的 Git 提交。

`complete_delivery_flow_survives_a_real_repository_and_bundle_roundtrip` 复用共享核心的需求收集、评审、任务、测试、Bug、验收、发布和改版链路，经真实操作文件保存、退出连接、重开、导出文件包和创建新副本后比较完整状态一致。Bug 独立复测交接记录、桌面逐项操作和服务模式仍按交付矩阵继续完善。

索引更新被触发器拒绝时，返回已保存、待索引恢复，源文件仍存在，相同操作重试不增加记录。源仓库中的冲突附件即使使用相同附件 ID，也保留两个内容文件，导出的文件包重建后仍有两份证据。

多文件导入中，测试将部分操作提前放入目标，其中可能包含先到达的子操作；持久恢复记录使重开能补齐父操作并恢复完整状态。坏哈希、坏格式或非法路径在新源文件安装前被拒绝。成员交接后原所有者保持停用，新副本使用当前成员权限。

Unix 测试还验证了元信息悬空链接不会在仓库外创建数据库、操作文件符号链接被拒绝、只读本地备份恢复后仍能写入，以及中文、空格和尾部空格目录可经文件包重建。

## 验证边界

这些证据覆盖真实本机仓库、目录交换和离线文件包，没有验证 HTTPS、SSH、远端 Git 服务、网络断开或远端竞争更新。同步中心、上传进度、三模式初始化、桌面程序重启、服务账户及 PostgreSQL 仍未由本记录证明完成。

本轮没有新的应用网络监听代码，正式桌面程序的端口、安装包与目标平台仍需单独验收。完整交付范围没有缩小，见 [交付矩阵](../05-交付进度.md)。
