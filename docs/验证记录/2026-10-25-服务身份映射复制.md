## 服务复制专项

测试位于 `crates/server/tests/cases/migration.rs`：

1. `mapped_accounts_keep_historical_ids_and_continue_through_backup_and_export`：历史身份与真实账户不同；核对 `actor_id`、`account_id`、完整状态、附件、旧回执、新评论及成员变更。新登录名与历史标签同名时保持不同身份，页面账户资料仍显示实际登录名。重复导入不覆盖后续变化；服务备份恢复后快照相等，再导出为本地继续保存。
2. `mapping_validation_and_uuid_collisions_never_grant_an_owners_role`：空映射、复用、未知、额外身份拒绝；历史所有者 UUID 与另一真实账户相同也不授予所有者权限。管理员仍遵守空间角色，未绑定账户不可读；禁止同一账户重复认领身份。
3. `mapped_last_owner_disable_and_global_account_state_remain_enforced`：映射后的普通所有者可导入；最后所有者不能被全局停用。全局停用使会话失效、不能接收提及；仅有停用所有者的映射拒绝。导出必须先明确停用仍启用的空间身份，不能借本地／Git 复制复活账户权限。
4. `failed_commit_keeps_only_retryable_blobs_and_origin_corruption_is_detected`：通过延迟外键约束使附件安装后的数据库提交失败，检查空间和身份记录全部回滚；去除注入约束后同包可重试。损坏原回执索引或来源校验值时，旧请求、导出及备份失败，目标包不冒充完成。
5. `unavailable_sources_invalid_tokens_and_missing_history_never_become_success`：拒绝非法令牌头及缺失源目录；伪造额外回执索引、删除原始来源或初始所有者时明确失败。核对失败请求不改动业务快照，修复测试中注入的初始损坏后可正常导出。
6. `executable_copy_commands_use_explicit_mapping_and_never_print_the_session`：实际编译产物执行两次导入和一次导出，核对交换包模式与成功状态；标准输出不含会话或数据库地址。
7. `abandoned_branch_actors_need_mappings_but_gain_no_live_membership`：真实 Git 并行成员提案及后续作者操作被明确放弃；导入仍要求完整历史身份映射。放弃提案不能借原 ID 重放，历史作者也不因此获得当前空间访问权；服务备份及再导出保留原身份。

## 真实 HTTP 完整流程

`workspaces::full_delivery_runs_through_service_roles_and_replays_from_postgres_after_reconnect` 使用独立编译服务进程和实际 TCP HTTP 完成需求、开发任务、测试失败、Bug 修复、独立复测、需求验收及发布，核对操作者和越权拒绝；重启后再读取，从 PostgreSQL 原始日志独立重放比对。

随后恢复完整服务备份到另一临时数据库，重新登录、下载真实附件并继续评论；再执行源服务导出 → Git 导入与导出 → 本地导入并追加评论 → 本地导出 → 另一服务显式映射导入。最后一台服务使用完全不同的真实账户 UUID，并启动独立 HTTP 进程：核对完整业务状态（仅空间命名空间按复制调整）、历史、发布、关联及附件，继续评论、下载和导出。进程通过正常关闭路径退出。

该证据使用实际 PostgreSQL、文件系统、系统 Git 和网络请求；专项接口测试则调用实际 Axum 路由。两者不能混同为浏览器／桌面点击验收。
