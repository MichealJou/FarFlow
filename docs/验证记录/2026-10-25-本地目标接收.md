### 三项核心专项

位于 `crates/core/tests/transfer.rs`：

1. `local_target_stages_same_ids_receipts_and_bytes_then_activates_and_restores`：使用共享源协议生成正式包，核对本地目标完整状态、来源、实际附件和原始回执。暂存期间旧连接和新命令不可写，附件、复制导出及发起下一迁移也拒绝。错误凭据、角色和过早时间均失败；合法激活及重试只有两条事件，公开事件不含令牌。暂存／激活备份恢复保留阶段；目标有新业务后重试不覆盖；本地作为后续源时可以冻结和取消，不能重用早期计划。
2. `local_target_rejects_wrong_packages_actors_paths_and_preserves_existing_directories`：普通包、错误目标模式、无权限成员、未知成员、负数或过早时间、源内路径、现有文件、符号链接、已有不同空间和损坏附件均拒绝，原文件与空间保持不变。共享源协议取消后不能发放完成凭据，旧本地目标继续只读。
3. `local_target_activation_rolls_back_event_failures_and_rejects_damaged_earlier_audit`：实际 SQLite 连接不能修改暂存对象或插入操作。注入阶段事件写失败后，控制与事件一起回滚，阶段仍是暂存；移除故障后激活成功。将较早事件改为开发者并重算指纹，读取与冷启动仍拒绝。修复原记录后可继续；所有者交接并停用原成员后，旧成员不能凭旧包重新暂存，新所有者重试已完成激活也不会改写历史操作者。

核心专项的源是共享 `TransferState` 协议对象，用于本地适配测试；不将它冒充 Git 源冻结或实际服务。实际服务方向由下面的数据库及 HTTP 验证另证。

### 真实服务专项

`migration::service_to_local_handoff_preserves_real_client_origins_and_cancellation_stays_read_only` 使用测试自建 PostgreSQL 和真实账户会话：

- 从已有复制空间及实际服务评论取得切点，保留服务原始客户端请求和来源链；历史所有者 ID 与登录账户 ID 不同。
- 冻结后源请求重试返回冲突；本地只接受历史所有者暂存，完整状态与字节一致。
- 非所有者不能完成服务交接；服务事务提交完成后，本地核对凭据激活并继续评论。
- 重试暂存保留本地新操作；再次复制导出保留客户端来源原文，备份恢复保留全部状态且可续写。
- 第二个实际服务空间取消源迁移后恢复写入，旧本地目标仍只读，另一空间的合法凭据也不能激活它。

### 独立进程与真实 HTTP 完整交付

扩展已有 `workspaces::full_delivery_runs_through_service_roles_and_replays_from_postgres_after_reconnect`，保留原有需求 → 任务 → 测试失败 → Bug 修复 → 独立复测 → 产品验收 → 发布链路及全部断点验证。

完整已发布空间从本地正式交接到独立服务、经真实 TCP HTTP 续写后，再由服务正式交给本地，逐字段比较全部核心规范文本。暂存阶段本地不能写；服务确认完成后，向旧源真实 HTTP 提交评论返回冲突。合法凭据激活本地，再实际停止服务进程，本地仍能继续回复、读取原始附件、保存完整备份并恢复全部状态；已发布快照始终相等。

迁移管理通过实际库接口执行，服务业务通过独立进程的真实 HTTP 执行，本地业务直接访问 SQLite。三种证据分别记录，没有把它们当作桌面 UI 操作。

## 自查与剩余范围

测试只使用临时 PostgreSQL、临时 Git 仓库和本机回环 HTTP，没有操作公司禅道、已有业务数据库或外部仓库。结束后未发现遗留 FarFlow 服务、测试运行器或本轮临时 PostgreSQL；其他项目进程未操作。

当前正式方向为本地 → Git、服务 → Git、本地 → 服务、服务 → 本地。Git 源的停写与离线副本确认、客户端界面、正式迁移 CLI、性能、旧格式升级、安装包和最终禅道比对仍未完成。配色第六轮尚待用户选择。全目标继续进行，见[本地接收协议](../17-本地目标接收与离线接续.md)及[交付矩阵](../05-交付进度.md)。
