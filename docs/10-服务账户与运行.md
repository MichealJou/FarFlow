# 服务账户与运行

服务代码位于 `crates/server`。账户服务已接入真实 PostgreSQL，提供管理员初始化、建号、登录退出、资料修改、改密、重置、停用、会话和账户操作历史。工作空间、业务命令及附件也已接入，详见 [服务工作空间协议](11-服务工作空间与业务协议.md)；完整客户端及部署交付尚未完成。

本地和 Git 模式仍不需要运行 FarFlow 服务。Redis 没有接入，也不是当前运行条件。

## 依赖与存储

| 依赖 | 原因 |
| --- | --- |
| Axum、Tokio | 提供 HTTP、JSON、异步网络和退出处理，复用现成运行时 |
| SQLx Core、PostgreSQL 驱动 | 参数化数据库操作、事务、连接池和 PostgreSQL TLS 连接能力 |
| RustCrypto Argon2 | 直接使用 Argon2id 口令哈希和随机盐，不自行实现加密算法 |
| Tower | 仅测试使用，直接调用实际 Axum 路由；另有真实 HTTP 进程测试 |

SQLx 总入口的可选 SQLite 绑定与现有 rusqlite 的原生链接版本冲突，因此直接依赖同版本的 SQLx Core 和 PostgreSQL 驱动，保留现有本地存储实现。版本由 `Cargo.lock` 固定。依据：[Axum 文档](https://docs.rs/axum/0.8.9/axum/)、[SQLx 事务](https://docs.rs/sqlx/0.8.6/sqlx/struct.Transaction.html)、[RustCrypto Argon2](https://github.com/RustCrypto/password-hashes/tree/master/argon2)。

| 表 | 数据 |
| --- | --- |
| `ff_accounts` | 固定账户 ID、规范化账号、姓名、部门、启用状态、服务管理员标记、初次改密标记、资料版本和口令哈希 |
| `ff_sessions` | 会话令牌 SHA-256、账户 ID、创建和绝对过期时间；不存原始令牌 |
| `ff_login_attempts` | 账号维度的失败次数、窗口和暂时限流时间，跨服务实例共享 |
| `ff_account_events` | 账户变更、操作者、时间和公开资料前后快照；不写入密码、密码哈希或会话令牌 |

账户写入和审计使用同一事务。首位管理员和管理员权限变更还使用数据库事务锁，避免两个并发请求移除最后一名启用管理员。资料修改采用版本比较，过期版本返回冲突。

完整服务备份恢复及目录身份绑定已接入，见 [备份与恢复](12-服务备份与恢复.md)。当前仍使用首版建表脚本，后续升级和旧版本迁移尚未完成。

## 本机运行

需要 Rust 1.88 或以上和可用的 PostgreSQL。为 FarFlow 准备独立数据库及具有建表权限的数据库角色，通过本机环境设置 `DATABASE_URL`。连接口令不写入项目、业务数据仓库或文档。

编译和查看用法：

```sh
cargo build -p farflow-server --offline
cargo run -p farflow-server --offline -- --help
```

初始化首位管理员前设置 `FARFLOW_ADMIN_ACCOUNT`、`FARFLOW_ADMIN_NAME`、`FARFLOW_ADMIN_PASSWORD`，然后运行：

```sh
cargo run -p farflow-server --offline -- init-admin
```

仅空账户库允许初始化；没有匿名注册管理员的 HTTP 接口。完成后从当前环境移除 `FARFLOW_ADMIN_PASSWORD`。随后启动：

```sh
cargo run -p farflow-server --offline -- serve
```

默认监听 `127.0.0.1:4640`，可通过 `FARFLOW_LISTEN` 指定地址。实际启动地址会输出，数据库地址、密码和令牌不输出。Ctrl+C 触发正常退出。当前实测为本机回环 HTTP；外部访问的 TLS、反向代理和部署尚未验收。

附件目录使用 `FARFLOW_DATA_DIR`，默认 `.runtime/service`；数据库和规范目录通过存储身份绑定。库级接口 `Server::connect` 接收数据库地址和目录两个参数。请使用 [完整备份命令](12-服务备份与恢复.md) 保存同一快照中的服务数据及附件，搬迁到空数据库和独立目录时使用恢复命令。

## API 与流程

| 接口 | 权限与实际结果 |
| --- | --- |
| `POST /api/auth/login` | 账号和密码；成功返回一次原始令牌、过期时间和公开资料 |
| `GET /api/auth/me` | 查询当前有效会话对应资料，含初次改密标记 |
| `POST /api/auth/logout` | 注销当前会话 |
| `POST /api/auth/password` | 校验原密码后修改本人密码，撤销该账户全部旧会话 |
| `GET /api/users` | 服务管理员读取账户列表，不含密码哈希和令牌 |
| `POST /api/users` | 服务管理员建号；新用户首次登录必须改密 |
| `PATCH /api/users/{id}` | 服务管理员修改姓名、部门、启用和管理员标记；携带当前资料版本 |
| `POST /api/users/{id}/password` | 服务管理员重置密码，撤销全部会话并要求再次改密 |
| `GET /api/users/{id}/history?after=0` | 服务管理员读取历史，每页最多 100 条；`next` 非空时继续按游标获取 |

受保护接口使用 `Authorization: Bearer 令牌`。认证方案名称按 [HTTP 标准](https://www.rfc-editor.org/rfc/rfc9110.html#name-authentication-scheme)忽略大小写；令牌本身保持原样。

账户名去除两端空格并转小写，允许 3 至 120 位字母、数字及 `. _ @ -`。密码至少 12 个字符、最多 128 字节，不要求特定字符组合；不裁剪或改写密码。姓名和部门各不超过 120 字，姓名不能为空，不允许控制字符。

会话绝对有效期为 8 小时，每次请求查询数据库中的当前账户与会话状态。停用账户、变更管理员权限、改密或重置都会使旧会话失效；重新启用不恢复旧会话。未知账户、密码错误和停用账户使用相同登录错误。10 分钟窗口内累计 5 次失败后，暂时阻止该账号 5 分钟，并返回重试等待时间；未知账号同样计数。

新建或重置后的账户可以查询本人、修改密码和退出；完成改密前不能管理账户。接口使用中文错误，拒绝未知字段，对响应设置不缓存及内容类型保护。密码运算放到阻塞线程并限制并发，避免在异步执行线程直接计算。

## 接入完整服务模式前的工作

服务管理员与工作空间所有者、产品、开发、测试等角色分开。真实账户 ID 已绑定共享核心成员，操作者和时间由服务端提供。工作空间隔离、最后所有者交接、业务事务幂等、停用账户的指派检查和附件权限已纳入 [工作空间验证](验证记录/2026-10-25-服务工作空间.md)。

当前没有公开注册、邮件找回、外部登录或多因素认证。用户管理已接入[共享界面](19-共享界面与浏览器运行.md)，账号和空间角色分别管理；服务会话仅保存在客户端内存。持久凭据安全保存、旧格式升级、公网部署与压力测试尚未完成。完整服务备份及目录绑定的运行与限制见 [备份与恢复](12-服务备份与恢复.md)。整体进度以 [交付矩阵](05-交付进度.md) 为准。
