# 服务网页托管

服务模式可以由同一个 Rust 进程提供网页与 `/api` 接口。生产运行不需要 Vite、Node.js 常驻进程或 Tauri。桌面服务客户端仍使用同一套 API。

## 构建与配置

先在根目录执行 `npm run build`，生成 `apps/web/dist/client`；执行 `cargo build -p farflow-server --release --offline` 生成服务可执行文件。配置 `DATABASE_URL`、`FARFLOW_DATA_DIR` 和已有服务管理员后，运行 `farflow-server serve`。初始化首位管理员的规则见[账户与运行](10-服务账户与运行.md)。

需要托管网页时，另设 `FARFLOW_WEB_DIR` 为网页 `dist/client` 的绝对路径。未设置时保留仅 API 运行方式。网页目录应与数据库附件目录分开，并由部署者管理。服务启动时会核对 `index.html`、`assets` 及资源文件，拒绝目录重叠、符号链接和特殊文件；配置错误时不会输出已启动信息。

浏览器访问服务根地址，选择服务模式后，默认地址就是当前服务。网页及接口同源，不依赖开发代理。当前公开路径为 `/` 和 `/assets`，其他构建目录文件不会自动公开。页面没有额外的路径路由，不需要把 `/api` 的错误回退成 HTML。

## 文件及响应

静态文件复用 `tower-http` 0.6 的 `ServeDir` 和 `ServeFile`，使用其 MIME、HEAD、路径和流式响应能力。该依赖专用于正式网页托管；没有自写文件服务器。所有网页响应使用重新验证缓存策略，并设置禁止 MIME 猜测、禁止被外站嵌入及内容安全策略。浏览器会话仍在内存中，网页刷新后需重新登录。

网页只包含应用资源；账号、会话、业务数据、备份和附件不会放入 `dist/client`。附件仍通过受认证的工作空间接口读取。

## 已有运行证据及剩余边界

2026-10-25 已使用独立临时数据库和本机回环地址运行真实可执行服务，验证首页、脚本、API 登录及未知 API 的 JSON 错误；单测另覆盖 HEAD、路径穿越、未公开文件、缺少构建资源、重叠目录和符号链接。

实际浏览器在 Rust 服务端口打开优化网页，完成登录、读取已有空间、创建文档、切换页面后重开详情，读取到原保存内容；随后用优化服务可执行文件重启，重新登录后仍读到原文档。控制台无错误和警告。没有通过 Vite 代理完成这条验收链路。

这属于本机真实进程验收。公网域名、HTTPS 反向代理、容器镜像、生产凭据及云服务器部署尚未验收，不能把本机结果描述为已上线。
