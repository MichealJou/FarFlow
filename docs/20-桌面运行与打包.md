# 桌面运行与打包

桌面和浏览器复用 `packages/ui` 与 `packages/client`。桌面入口在 `apps/desktop`，Tauri 壳使用独立 Cargo 工作区，避免服务构建引入 WebView、窗口和系统对话框依赖。

## 三种入口

| 模式 | 初始化及身份 | 业务访问 | 持久化 |
| --- | --- | --- | --- |
| 本地 | 系统对话框选父目录，填写新文件夹、空间及首位成员；重开后明确选择成员 | 原生 IPC → `crates/desktop` → 共享核心 | 所选目录中的 SQLite 和按 SHA-256 保存的附件 |
| Git | 同样通过系统目录授权创建或打开独立业务仓库；明确选择成员 | 原生 IPC → 桌面适配 → Git 核心 | 不可变操作 JSON、附件及可重建 SQLite 索引；使用系统 Git |
| 服务 | 填写服务 URL，以真实服务账号登录 | 官方 HTTP 插件 → 与浏览器相同的 API | 独立 Rust + Axum 服务、PostgreSQL 及服务附件目录 |

本地和 Git 依赖操作系统文件权限，选择成员是记录实际操作者，不是密码验证。不会把打开空间自动视为所有者登录。服务会话保存在客户端内存；退出后撤销会话。

## 目录及提交边界

网页只能持有原生选择器返回的目录授权标识，不能直接提交任意本机路径。新文件夹禁止跨目录、保留名称及覆写现有空间。每次读取、命令或附件操作均重新打开并核对空间 ID，防止目录被替换后误写其他空间。

每个打开会话单独绑定路径和成员。命令在存储事务或仓库锁内核对空间修订；过期修订拒绝写入。重复操作 ID 只能重取原请求的结果，不能改写原请求。附件通过二进制 IPC 传输，前端和原生入口都限制为 10 MiB，并由共享核心计算哈希。

Git 索引保存警告会返回界面。业务或附件已保存、后续刷新失败时，界面明确提示已保存，避免误导用户重复创建。文本预览按 UTF-8 读取并作为文本呈现；图片和 PDF 保持独立预览。

## 构建与测试

根目录执行 `npm run desktop:dev` 启动桌面开发入口；`npm run desktop:build` 构建当前系统的优化 App。前端正式构建自动包含在打包步骤中。SQLite 已通过 rusqlite 的 bundled 特性随应用构建，不需要额外安装数据库。

桌面库纳入根工作区的 Rust 测试；Tauri 壳单独验证：

```sh
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml --offline
cargo clippy --manifest-path apps/desktop/src-tauri/Cargo.toml --offline --all-targets -- -D warnings
cargo llvm-cov --manifest-path apps/desktop/src-tauri/Cargo.toml --offline --json --output-path .runtime/desktop-shell-coverage.json
```

壳测试使用实际生成的 IPC 分发器与原始附件字节，包含参数拒绝、中断、失效会话以及真实 capability 配置。服务地址权限覆盖 HTTP、HTTPS 默认及自定义端口；不允许 `file:` 等协议。完整根工作区和壳的覆盖率分别记录，不能把只执行壳测试时未运行的依赖代码计为已验证。

## 正式迁移命令行接续

CLI 接续阶段未重新构建 App，使用上述 22.86 MiB 决策历史包。通过原生界面新建 SQLite 空间、文档、评论并上传中文附件后，关闭空间，使用独立优化版 `farflow-migrate` 连续完成本地 → Git → 本地正式交接。目标与原始完整业务状态一致，保留空间和工作项 ID、成员、评论及实际附件字节；App 重开选择原成员后，原附件可预览，第二条评论实际保存成功。CLI 构建与六方向真实进程验证见[使用说明](23-正式迁移命令行.md)，不等于桌面迁移向导已交付。

本轮曾在同一 App 进程后续打开目录选择器时出现 Open 和 New Folder 按钮禁用，重启可以恢复，原因尚未确认，未做猜测性修改。迁移后的首次重开采用了重启。随后另建独立回归空间，同进程重复目录选择、取消附件选择、实际上传附件和再次重开均成功，说明该问题当前并非每次出现，仍保留为偶发待查项。证据在 `/private/tmp/farflow-qa/migration-cli/`；原生 JavaScript 控制台本轮仍未单独采集。
