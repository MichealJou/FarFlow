# 服务身份映射与三模式复制

本地、Git 和服务均可导出同一交换目录，再复制成另一模式的新工作空间。实现复用共享核心和已有附件校验；没有增加 Redis 或新的第三方依赖。这里的操作是**复制**：源仍可写，目标使用新空间 ID。保留同一空间 ID 的正式交接另见 [统一迁移](15-正式迁移与交接.md)、[服务交接](16-服务正式迁移与账户交接.md)、[本地接收](17-本地目标接收与离线接续.md)及[Git 源确认](18-Git源交接与冻结确认.md)。

## 历史身份与登录账户

历史成员 ID 用于原始操作、负责人、评论提及、测试事实和发布快照；服务账户 ID 用于登录、改密、全局停用和会话。导入时不改写历史成员 ID，也不按姓名或登录名自动认领。

`ff_workspace_identities` 保存空间内的 `member_id → account_id`。必须覆盖完整操作图出现过的全部身份，包括停用成员、放弃分支作者及已不在当前成员列表的人。同一空间内，一个历史身份只绑定一个真实账户，一个真实账户也只能绑定一个历史身份。绑定历史人本身不会让已放弃分支中的人获得当前成员权限。

导入要求所有映射账户存在，且至少一位当前启用的历史所有者对应启用的真实账户。当前已改密、启用的服务管理员或映射后的启用所有者可以导入；服务管理员不因导入他人空间而自动取得业务权限。即使历史所有者 UUID 恰好等于另一服务账户 UUID，也不能绕过显式映射获得权限。

服务请求从登录会话查出真实账户，再按绑定取得历史操作者。工作空间内的最后有效所有者检查使用真实账户状态；全局停用、会话撤销、指派及提及限制仍然生效。

## 页面使用的数据

空间快照增加 `actor_id`，表示当前会话在该空间的历史成员 ID。`accounts` 每项的 `id` 是历史成员 ID，`account_id` 是真实服务账户 ID，其余资料来自当前账户。`state` 继续保留原始业务和历史。

空间所有者的账户目录返回真实账户 `id`，并提供可空的 `member_id`。添加新人使用真实账户 ID；已有绑定必须使用返回的历史 `member_id`。同一账户不能借另一 ID 再加一遍成员。

成员变更仍要求当前空间修订号。姓名和部门取真实账户资料；已有历史成员的域内账号标签保持稳定。新登录名若与另一个历史人的标签相同，生成以成员 UUID 为基础的唯一标签，当前登录名仍由 `accounts` 显示，避免按同名误合并。

## 接口与命令

| 接口 | 行为 |
| --- | --- |
| `MigrationHistory::validate` | 校验来源链、完整图、客户端原始请求与实际操作，以及未解决冲突 |
| `MigrationHistory::attachments` | 列出完整图的历史附件，包括放弃提案中的字节 |
| `MigrationHistory::member_ids` | 收集当前及全部历史分支出现的身份 |
| `MigrationHistory::export_copy` | 使用现有交换协议导出并核对附件 |
| `MigrationArchive::open` | 预检交换目录，复制为已校验的私有临时副本 |
| `MigrationArchive::report` | 提供源空间、数量、成员及全部身份 ID |
| `MigrationArchive::copied_history` | 创建新空间命名空间及可核对的来源链 |
| `MigrationArchive::write_blobs` | 安装已验证的历史附件，沿用不可变内容校验 |
| `ClientOperation::verify_effective` | 核对客户端原始命令和服务实际命令，仅允许成员资料规范化 |
| `Server::import_copy` | 显式账户映射后导入新服务工作空间 |
| `Server::export_copy` | 当前空间所有者导出同一交换格式 |

先设置目标服务的 `DATABASE_URL`、`FARFLOW_DATA_DIR` 及当前已改密会话 `FARFLOW_SESSION_TOKEN`。令牌不放在命令参数、JSON 映射或项目文件中。

```sh
cargo run -p farflow-server --offline -- import-copy /交换目录 /私有位置/身份映射.json 新空间UUID
cargo run -p farflow-server --offline -- export-copy 空间UUID /独立位置/新交换目录
```

映射 JSON 是“历史成员 UUID”为键、“真实账户 UUID”为值的对象。先用 `inspect_migration` 或 `MigrationArchive::report` 获取 `identity_ids`，完整核对后填写映射。命令只输出核对报告，不输出令牌、连接或密码。完成后从当前环境移除 `FARFLOW_SESSION_TOKEN`。

这些命令针对能够直接访问服务数据库和数据目录的本机管理环境，没有允许远端客户端传任意服务路径的 HTTP 接口。远端受控上传、账户选择及核对向导仍待接客户端。

## 幂等、历史与原始字节

服务新表 `ff_workspace_origins` 保存完整来源图，`ff_workspace_origin_operations` 保存其原始请求、客户端请求和历史回执。载荷继续使用 TEXT，避免负零等核心指纹被数据库 JSON 类型改写。Git 清单增加可选 `clients`，没有客户端原始请求的旧清单保持原编码。

复制后的本地、Git、服务继续保存完整来源链；服务后续接受的客户端请求与规范化后的真实请求同时保留。成员资料规范化不能掩盖角色、启用状态、业务字段、操作 ID 或负零的变化。历史客户端请求不会包含服务会话。

原始成功操作重试返回原回执；不同操作者、同 ID 不同内容、放弃提案或冲突决策 ID 均不能被当成新的业务写入。服务导入重试要求同一创建者、同一来源和同一原始身份映射，核对当前历史与全部字节后返回原复制报告，不覆盖导入后的新操作。

导入事务失败会回滚空间、绑定、来源、投影及索引。已经安装的不可变字节可以留待同包重试，不冒充已完成的业务记录。交换目录、源数据与目标运行目录必须独立；链接、未知内容、损坏字节、来源不符或未解决冲突会被拒绝。

## 停用、导出与备份

全局停用和空间停用分开保留。如果服务账户已全局停用、但其历史空间身份仍为启用，导出到无服务的本地／Git 会让它重新获得空间权限，因此当前拒绝这类导出，要求所有者先明确停用空间身份。导出不会静默篡改成员记录或伪造业务操作。

完整服务备份则保留真实账户、全局状态、历史身份绑定、完整来源图、原始客户端请求和所有历史字节。恢复后重新登录，原会话仍不恢复。早期无绑定字段的原生备份按原生同 ID 关系校验；导入空间不能用当前成员索引猜测历史绑定。

## 验证边界

真实 HTTP 完整链路在需求、任务、测试、Bug 复测、产品验收及发布后，已继续执行服务 → Git → 本地 → 另一服务的复制。新服务使用完全不同的真实账户 ID，按显式映射登录；比较完整状态及附件，再通过真实 HTTP 继续评论并导出。

专项测试还检查账号同名、UUID 撞号、无效／重复／缺漏映射、停用及最后所有者、历史放弃分支、原请求幂等、损坏来源索引、数据库提交失败重试，以及实际可执行程序的导入导出。最终执行结果见 [服务身份映射复制验证](验证记录/2026-10-25-服务身份映射复制.md)。

这仍不是三模式桌面产品验收。六条不同模式的正式交接方向均已另接入，最新增加[Git → 本地／服务](18-Git源交接与冻结确认.md)；远端向导、可运行前端、规模性能与三平台验收仍按 [交付矩阵](05-交付进度.md) 继续。
