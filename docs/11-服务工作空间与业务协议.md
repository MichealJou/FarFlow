# 服务工作空间与业务协议

实现位于 `crates/server/src/workspace.rs`。工作空间、账户权限、业务命令、评论与附件已接到可运行服务，业务判断继续调用 `farflow-core`；本地、Git、服务模式没有分别实现三份状态机。Redis 不参与当前实现。

## 数据与事务

| 位置 | 当前保存内容 |
| --- | --- |
| PostgreSQL `ff_workspaces` | 工作空间 ID、名称、创建账户、修订号、初始状态、完整业务投影及校验值 |
| `ff_workspace_members` | 工作空间和真实账户的关联、成员启用及所有者标记，用于空间列表和有效所有者检查 |
| `ff_workspace_operations` | 客户端规范请求、服务端真实请求、回执及修订号；正常接口只追加新操作 |
| `ff_workspace_identities` | 原始成员 ID 与当前服务账户的一一显式绑定 |
| `ff_workspace_origins`、`ff_workspace_origin_operations` | 导入空间的完整来源图、原始客户端请求及历史回执索引 |
| `FARFLOW_DATA_DIR/workspaces/空间ID/attachments/哈希前两位/哈希` | 实际附件字节，按工作空间隔离和内容去重 |

初始状态、投影及操作载荷使用 **TEXT 保存核心规范 JSON 文本**。边界测试证明 JSONB 会规范化负零，使核心指纹和后续读取校验不一致；当前实现保留 `-0.0`、换行、制表符及规范请求编码，并在启动时拒绝不兼容的早期 JSONB 试验格式。数据库的 JSON 类型转换会处理输入表示，见 [PostgreSQL JSON 文档](https://www.postgresql.org/docs/16/datatype-json.html)；原始请求身份由应用层规范编码负责。

一次业务写入先取得工作空间行锁，检查身份和当前状态，执行同一核心命令，再在同一事务内更新投影、原始操作、回执与必要的成员索引。SQL 失败不留下半次业务变更。并发修改同一旧对象版本时，只有一个成功，另一个返回冲突。

账户管理写入使用身份事务排他锁，工作空间操作取得对应共享锁，再按固定顺序取得账户及工作空间锁。这样不同空间可并行操作，账户停用和所有者变更共同保护“至少一位有效所有者”。锁的基础语义见 [PostgreSQL 显式锁](https://www.postgresql.org/docs/16/explicit-locking.html)。

## 身份与角色

客户端提交操作 ID、可选的工作空间修订号和业务命令。操作者取自当前服务会话，时间取自数据库；请求不能带 `actor_id` 或 `at` 冒充别人。

服务管理员管理服务账户。工作空间所有者管理本空间成员；系统管理员身份本身不授予其他工作空间的业务权限。新建或重置密码后，完成改密才能创建或使用空间。

原生空间的新成员 ID 指向真实服务账户；复制导入的历史成员 ID 通过显式绑定指向真实账户，不能按 UUID 相等、姓名或账号猜测权限。添加或更新成员时，姓名和部门取服务数据库资料，已有成员的域内账号标签保持稳定，当前登录名通过快照账户资料显示；客户端只决定目标身份、角色与成员启用状态。成员变更必须携带当前工作空间修订号，防止旧名单覆盖新权限。详细映射、同名处理及复制协议见 [服务身份映射与三模式复制](14-服务身份映射与三模式复制.md)。

工作空间成员启用状态和服务账户启用状态分别保留。快照的 `state.members` 表示空间内状态，`actor_id` 是当前会话在此空间的历史成员 ID；`accounts` 的 `id` 是历史成员 ID，`account_id` 是真实账户 ID，并提供当前服务资料及账户状态，便于界面解释停用来源。已停用账户不能接收新的指派、提及或被启用为有效成员；历史内容保留。

停用账户前检查其拥有的使用中或尚待交接空间；仍是最后一名有效所有者时拒绝停用，须先交接。已确认完成迁移的只读源不再阻挡旧账户停用，但保留历史及管理员完整备份，不授予管理员额外业务权限。并发停用一个账户、撤销另一账户的所有者角色，也不能让使用中的空间无人管理。

## 接口

| 接口 | 行为 |
| --- | --- |
| `GET /api/workspaces` | 仅列出当前账户属于且成员启用的空间 |
| `POST /api/workspaces` | 当前账户创建空间并成为所有者；提交 ID 和名称；同一创建者的相同初始化可重试 |
| `GET /api/workspaces/{id}` | 返回模式信息、核心状态和当前成员账户资料 |
| `GET /api/workspaces/{id}/items` | 复用核心筛选和统计，支持类型、文本、状态、负责人及产品等已有筛选字段 |
| `GET /api/workspaces/{id}/people` | 所有者检索可添加的启用账户，只返回基础资料；文本按字面匹配，每页最多 100 条，使用 `after` 和 `next` 游标 |
| `POST /api/workspaces/{id}/commands` | 执行核心业务命令；支持产品、项目、迭代、需求、任务、用例、执行、Bug、发布、文档、评论和成员 |
| `POST /api/workspaces/{id}/attachments` | 原始字节上传，查询参数提供操作 ID、附件 ID、对象 ID、名称和类型；哈希及大小由实际字节计算 |
| `GET /api/workspaces/{id}/attachments/{attachment}` | 检查空间、对象和附件状态，再校验字节并下载 |

业务命令字段为 `id`、`command`、可选 `expected_revision`。后者对成员命令必填；普通工作项继续使用核心的对象 `version`。相同操作 ID 的原请求重试返回原回执，不重复增加内容、评论、审计或修订号。不同内容或不同操作者复用 ID 返回冲突。回执和源操作缺失或损坏时返回错误，不伪造成功。

账户接口请求上限为 16 KiB，业务命令上限为 2 MiB，单次命令节点不超过 1000；批次项数与嵌套还需符合核心规则。附件上限沿用 10 MiB。已实测超过登录请求上限的正文可在业务接口保存，精确 10 MiB 附件可上传下载，超过上限被拒绝。

## 附件持久化

服务复用核心的 `write_attachment_bytes`、`read_attachment_bytes` 和目录持久化能力。先验证命令并持久化文件，再提交数据库引用；失败可能留下没有元信息引用的孤立文件，原请求重试可继续使用。孤立文件回收尚未实现。

同一内容不同文件名只保存一份字节；原文件名不作为磁盘路径。已经保存但字节意外缺失时，相同上传可补回缺失内容，不增加业务记录；已有文件内容不符时拒绝覆盖并报告错误。

目录和内容路径校验会拒绝不符合要求的链接。Unix 新建服务数据目录和子目录采用 `0700`，不改写已有目录权限；附件临时文件继续使用核心的私有文件权限和原子落位。下载使用二进制类型、禁止嗅探，并以 UTF-8 文件名提供下载，预览仍由未来客户端接入。

## 运行与当前限制

`Server::connect` 接收数据库地址和数据目录。可执行程序使用 `DATABASE_URL`、`FARFLOW_DATA_DIR`，后者默认 `.runtime/service`。数据库和规范数据目录已通过存储身份绑定；错误路径、损坏或缺失标记会被拒绝。搬迁使用完整备份恢复，不能直接替换附件目录，详见 [备份与恢复](12-服务备份与恢复.md)。初始化、登录和启动方法见 [账户运行说明](10-服务账户与运行.md)。

当前以完整核心投影加工作空间行锁执行业务，筛选在核心内存完成。1 万工作项、5 万操作的性能、数据库查询索引优化和压力测试仍未完成。启动校验格式，读取校验投影哈希，重试核对对应源操作；当前启动不会自动重放所有空间日志，测试会独立完整重放进行比对。

完整服务备份恢复、目录身份绑定及中断重试已有实际验证；服务 → Git 与本地 → 服务的正式交接见 [服务迁移协议](16-服务正式迁移与账户交接.md)。其余迁移方向、早期试验格式升级、孤立文件回收、细粒度产品数据权限、外部 TLS 部署、客户端界面及目标平台打包仍待完成。当前已经通过真实网络业务链路，不代表完整三模式桌面产品已交付。

证据见 [服务工作空间验证](验证记录/2026-10-25-服务工作空间.md)，全范围见 [交付矩阵](05-交付进度.md)。
