# 本地与 Git 复制协议

此协议最初实现本地与 Git 交换基础；现已接入 [服务身份映射与三模式复制](14-服务身份映射与三模式复制.md)。本地、Git、服务均能导出同一完整交换目录，再复制为另一模式的新工作空间。源空间保持原样，目标必须使用新的工作空间 ID 和独立目录。保留同一空间 ID 的正式交接另见 [统一协议](15-正式迁移与交接.md)及[Git 源确认](18-Git源交接与冻结确认.md)，不能把复制接口当成正式模式切换。

## 已实现接口

| 接口 | 实际作用 |
| --- | --- |
| `LocalWorkspace::export_copy(actor, destination)` | 在 SQLite 固定数据切点读取原始历史，要求启用的所有者，导出交换目录及核对报告 |
| `GitWorkspace::export_copy(actor, destination)` | 在仓库锁内读取完整因果操作图，要求启用的所有者，未解决冲突时拒绝导出 |
| `inspect_migration(source)` | 预检清单、元数据指纹、操作图、来源链、实际附件和目录，返回 `MigrationReport` |
| `LocalWorkspace::import_copy(source, destination, new_id)` | 预检后建立新的 SQLite 工作空间，保存完整来源及回执索引，核对重开后再落位 |
| `GitWorkspace::import_copy(source, destination, new_id)` | 预检后建立新的真实 Git 数据仓库，保留来源、操作图和附件，核对后再落位 |

表内是已执行的 Rust 库接口；服务导入导出另有本机管理 CLI，客户端向导尚未实现。需要已有目标父目录；交换目录和复制目标都不能位于源目录内，不能覆盖现有目录。这样不会向源 Git 数据仓库写入格式之外的文件，也不会改变原交换包。文件及目录链接、未知文件、损坏字节、缺失附件、无效来源和冲突均会拒绝。

## 交换目录

```text
交换目录/
  migration.json
  attachments/哈希前两位/完整哈希
```

`migration.json` 包含格式版本、包 ID、源模式、完整 `GitLog`、复制来源链、附件清单和元数据校验值。元数据上限为 512 MiB，附件最多 100000 个文件；单附件继续沿用 10 MiB。预检复制实际字节到私有临时目录并校验，导入只使用已验证副本，避免再次读取已经变化的原交换目录。

线性本地历史按原请求顺序转换为因果链。来自 Git 的并行分支、原始请求、依赖、设备及冲突决策均保留，不把最终投影伪装成一条新业务操作。复制只调整工作空间命名空间；用户、对象、操作、内容版本、评论、关联及附件 ID 保持。请求本身和原业务时间不变，所以请求指纹、已发布快照和历史测试事实也保持。

## 来源与核对报告

`MigrationOrigin` 保存来源包 ID、源与目标空间 ID、源模式、原始图前沿和原始历史校验值。来源链可以从当前图还原各次复制前的历史并核对，不能只改空间 ID 后声称原始来源仍有效。最多支持 32 次连续复制来源；超过边界会在目标落位前拒绝。

`MigrationReport` 区分源和目标模式、空间 ID、业务修订号与操作图节点数量，并提供工作项、评论、附件记录数量、实际历史字节文件数量、含停用状态的原成员资料及完整来源链。`identity_ids` 还列出全部历史身份，包括不在当前成员列表的放弃分支作者，用于服务导入时逐一绑定。`attachment_count` 是业务附件记录数，`blob_count` 包括已被冲突决策放弃但仍需保留的历史附件字节。两者不能混为同一数量。

SHA-256 和来源链用于完整性核对，不是来源系统的数字签名或身份认证。接收交换包意味着接收其中的完整空间和历史；包不携带服务密码、服务会话或数据库连接。

## 本地存储与历史回执

原生本地空间继续使用 SQLite 格式 1，不会在打开时被自动升级。复制得到的本地空间使用 SQLite 格式 2，增加 `migration_origin` 和 `migration_receipts`：前者保存完整来源图，后者保存原请求和回执，或者保留原提案及决策 ID。旧客户端会拒绝格式 2，避免将来源历史当成空白空间继续保存。

主动准备正式迁移时，先完成独立备份，再在事务中升级至格式 3 并增加迁移控制和写入屏障；格式 2 的来源及原回执继续保留。冻结中的源不能通过普通复制入口绕开交接，取消后可恢复正常业务和复制。

当前投影从来源图的固定状态开始，后续操作仍按现有 SQLite 事务保存。重开时校验来源图、初始投影、来源回执索引和后续操作。原始成功请求重试返回原回执；放弃的提案、冲突决策或同 ID 不同请求会返回冲突，不能借复制重新执行。复制后的本地备份包含 SQLite 来源表及所有历史附件，恢复后可继续保存和再次导出。

## Git 存储与后续协作

Git 工作空间清单增加可选的 `origins` 和 `clients`；没有复制来源及客户端原始请求的原生清单保持原编码。清单上限为 64 MiB。克隆、bundle 交换及远端同步会保留来源链和原始客户端请求；来源清单不同的空间不能直接合并。仓库新建及复制根目录使用私有临时目录落位，Unix 下根目录为 `0700`，文件沿用现有私有原子写入。

复制后的 Git 空间仍有完整操作文件和实际附件，可以继续业务保存、创建提交、使用 bundle 和现有远端同步。旧所有者被停用的事实不变，复制或克隆不会复活其权限。源空间和新空间拥有不同标识，后续变化分别保留，不会被自动当作同一个空间合并。

## 当前验证与剩余范围

已验证本地 → Git → 本地完整交付数据、评论、原始回执、负零及转义正文、墓碑、真实附件；未解决冲突拒绝；放弃提案的两份附件经过本地备份恢复和 Git bundle 后仍保留；停用原所有者、来源损坏、索引损坏、非法路径、现有目标保护及真实裸远端往返均有测试。完整需求、任务、测试、Bug、发布流程也再次通过双向复制核对。

服务真实账户一一映射和导入导出已接入，并验证真实 HTTP 服务 → Git → 本地 → 新服务后继续协作。本地 → Git 的正式交接另已接入冻结、暂存、完成凭据、激活和恢复；其他方向、Git 离线副本确认及客户端向导仍待完成。大空间性能、三平台及断电验收仍按原计划执行。
