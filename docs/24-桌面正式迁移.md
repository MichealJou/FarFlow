# 桌面正式迁移

桌面通过“设置 → 空间迁移”发起交接，通过初始化页“接收正式迁移”建立目标。原空间 ID、业务 ID、内容版本、操作者、评论和附件随原始历史交接，普通新建和 Git 副本创建继续使用各自原有流程。

本地和 Git 的源控制、目标暂存与激活已经接入原生 IPC，复用现有迁移库及与 CLI 相同的回执、凭据文件规则。服务端仍使用[正式迁移命令行](23-正式迁移命令行.md)在管理机器执行真实账户映射；浏览器服务迁移向导和受控远端文件交换继续开发，不能把桌面入口视作六方向远端向导已完成。

## 发起交接

1. 明确选择原空间实际成员，进入“设置 → 空间迁移”。所有者可以发起迁移；其他成员可查看阶段，Git 所需成员分别提交本人停写确认。
2. 选择原业务目录之外的“交接资料目录”和不同的目标模式，点击“保存备份并冻结源”。先保存独立备份，成功后源业务只读；备份失败不会冻结。
3. Git 源需要每位启用的可写成员先同步本人全部副本、停止业务写入，再在“Git 成员停写确认”填写说明并明确确认。提交本人声明不会替其他成员确认，也不代表系统锁住所有离线设备。迟到记录和已知并行计划须先核对处理。
4. 点击“导出正式交换包”。界面显示本机保存位置；交换包目录包含完整迁移元数据和真实附件。完整交给目标设备后，由目标核对并暂存，不能只传其中一个文件。

备份及交换包名称包含本次迁移 ID，保持分开存放。关闭界面或退出应用不会取消已经冻结的计划，重新打开源空间后从真实持久化阶段继续；路径授权需要重新通过系统窗口选择。

## 接收与回执

1. 在目标设备初始化页点击“接收正式迁移”，通过系统窗口选择交换包目录。界面校验附件和历史，显示原空间、方向、计划以及工作项、评论、附件数量。
2. 明确选择交换包内的启用所有者作为实际操作者，选择目标父目录及新文件夹，再选择独立的回执保存目录和文件名。不会自动取得所有者身份。
3. 核对后确认只读暂存。目标保留原空间及成员标识，继续拒绝业务写入。成功页先显示回执实际保存位置，再提供“打开暂存空间”，不会在回执提示出现前自动跳走。
4. 把目标回执交回源端。接收服务目标的交换包时，界面提示交给对应服务管理员；不会在本机误建成 SQLite 或 Git 空间。

回执保存位置必须在目标业务目录之外。相同正式包、目标和实际身份可重试；重试会核对原目标，保留目标激活后的新业务，不能用旧切点覆盖。

## 源完成与目标激活

源所有者重新进入“空间迁移”，选择目标回执及交接资料目录，核对目标后明确确认“源永久只读”，再保存完成凭据。源完成后不能取消或恢复旧源写入；已完成源可以用同一回执重新保存原计划的完成凭据。

目标所有者打开暂存空间，在“设置 → 空间迁移”选择源完成凭据，核对交接后明确确认激活。完成凭据不属于此计划时拒绝激活；目标继续只读。激活成功后目标可以继续业务，也可以在以后用新计划发起下一次迁移。

回执和完成凭据通过系统文件选择器授权，网页仅提交授权标识，不接收任意本机路径。完成凭据由 Rust 写入文件，界面与公开 IPC 结果不返回其令牌内容。文件采用同目录临时文件、持久化和禁止覆盖落位，新文件在 Unix 上为 `0600`；不同内容、文件链接和业务目录内输出被拒绝。

## 取消与失败重试

- 源完成前可明确确认取消。源恢复业务写入，已经暂存的目标仍只读；后续交接使用新计划。
- 回执、凭据或文件路径在预检时不符，会在改变阶段之前拒绝。预检之后仍可能发生磁盘和并发文件变化，错误不会自动回滚业务阶段或恢复旧源写入。
- 目标已经暂存而回执保存失败：保持只读，选择新回执文件，用同一包和实际身份重试。
- 源已经完成而凭据保存失败：源保持只读，用同一目标回执重新保存到新文件，再交给目标。
- 动作提交后重新读取阶段失败：界面明确提示已经保存和读取失败，提供重新读取入口；不把刷新失败说成已恢复写入。

## 验证与边界

核心文件策略、桌面适配、真实 IPC 分发及共享组件分别测试。本地与 Git 双向测试核对原始 ID、评论、附件字节、实际成员、取消、只读暂存、错误凭据、源完成、目标激活和目标续写后的重试。另以真实 SQLite 锁暂停阶段提交，在输出预检之后制造文件竞争，核对已提交阶段保留、不同输出不覆盖及可重试恢复。

macOS 的目录与文件选择器现明确绑定 FarFlow 主窗口，避免依赖对话框库自动选所属窗口；修复前出现过连续选择后确认按钮禁用，不能只凭编译或单测宣称原生问题已经解决。原生运行证据和当前完整交付边界以[交付进度](05-交付进度.md)为准，其他平台及服务远端向导仍需实际验证。

最终优化包已实际完成本地 → Git → 本地的连续向导操作及冷启动读取，原空间和文档 ID、完整历史、成员、评论和实际附件保留。Git 上续写第二条评论，本地上续写第三条，冷启动后均可读。此前确认按钮禁用在后台冷启动中仍可出现，面板置前后立即恢复；固定父窗口的连续流程已通过，但窗口激活边界仍继续核对，不能把重启或置前当成彻底修复。原生证据见 `/private/tmp/farflow-qa/transfer-ui/`。
