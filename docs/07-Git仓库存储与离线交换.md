# Git 仓库存储与离线交换

当前仓库适配位于 `crates/core/src/repository.rs`，直接复用共享业务核心、操作图、本机附件和原子文件能力。Git 交给系统 Git 命令处理，不启动额外数据库或业务服务；禁止覆盖的原子目录落位依赖说明见[桌面 Git 同步](22-桌面Git同步.md)。当前已完成真实仓库的本机保存、提交、目录交换、Git bundle 文件包和恢复；[远端获取、上传与同步](08-Git远端同步.md)位于 `repository/remote.rs`。

## 实际目录

```text
业务数据仓库/
  workspace.json
  operations/操作ID前两位/操作ID.json
  attachments/内容哈希前两位/内容SHA256
  transfers/记录ID前两位/记录ID.json
  .git/
    farflow/
      device.json
      lock.sqlite
      index.sqlite
      pending/
      parents.json
      source-transfers/计划ID.json
```

`workspace.json` 包含格式、模式、工作空间信息和初始状态。每个业务操作或冲突决策为一个不可变 JSON 文件，Markdown 正文目前保存在业务载荷中。附件按真实字节的 SHA-256 保存；所有原始提案引用的附件都保留，包括尚未解决的冲突。独立 Markdown 文件导出仍待完成。

`transfers` 是[Git 源正式交接](18-Git源交接与冻结确认.md)的追加冻结、成员确认和结束记录，纳入同一不可变文件树及历史检查。冻结后拒绝业务写入，传输仍用于传播迁移状态；迟到分支保留并阻止旧计划首次完成。

`.git/farflow` 保存当前副本的设备身份、写入锁、可重建索引、恢复记录及私有源控制，不进入业务提交或普通文件包。通过普通文件包创建的新副本生成新的设备身份，业务成员及历史操作 ID 保持不变；专用私有恢复接口会在核对后恢复发起设备。当前数据仓库使用独立的 `main` 分支，不直接混入项目源代码仓库。

## 保存与状态

保存先执行共享业务校验，再落位附件和操作文件，最后更新 SQLite 派生索引。源文件是权威，索引丢失或损坏时可重建。多个应用句柄通过本机 SQLite 写锁协调，不共用网络目录中的运行中数据库。

`GitSave` 返回业务回执、索引是否更新，以及必要的恢复说明。操作已持久保存但索引更新失败时，返回“操作已保存在本机，索引待恢复”；相同操作 ID 重试不会重复产生业务记录。

本机保存与 Git 提交分开。`commit` 将已校验的数据文件写入 Git；完整导出文件包时会先固定一次本机快照。这两个动作本身没有调用远端上传，不能把这些结果显示为团队已经收到。远端上传使用独立的 `push` 或 `sync`，结果单独报告。

## 离线交换与恢复

`.farflowpack` 使用完整 Git bundle，包含当前数据树及其 Git 历史。导入通过临时对象库读取文件树，不检出包内内容。仅接收已知清单、操作、内容附件及交接记录路径，拒绝符号链接、可执行文件及额外脚本路径；逐文件限制大小并校验业务数据、因果依赖、交接记录和附件内容。

创建新副本也检查可达历史中是否修改或删除过不可变的清单、操作、附件和交接记录；不能仅凭最新文件树合法就接受曾经删改的业务历史。单次操作在落盘前检查 2 MiB 上限，超限拒绝且不改变已有工作空间。

导入与本机数据按同一操作图合并。已有操作 ID 的内容不一致时拒绝覆盖；正常并发按语义合并或进入问题集合。双方原始提案和明确决策仍保留。重复导入不增加对象、评论、审计或业务修订。

多文件合并先把完整待导入文件和哈希清单保存到本机 `pending` 记录。恢复前构建完整候选数据并验证；部分文件已落位时继续完成，未验证的半包不返回成功。损坏恢复记录会保留并报错，便于后续恢复处理。

业务文件导入和 Git 提交关联分开处理。Git 关联记录失败时，错误明确表示“业务数据已导入，Git 关联待恢复”，重试不会重复导入。文件包导入后的本机提交保留双方 Git 祖先，采用正常提交，不强制重写历史。

## 用户与权限

业务命令继续执行成员、角色、停用和最后所有者保护；完整文件包导出要求启用的所有者。创建副本只是恢复已有业务，不冒充初始所有者，不重新启用已停用成员。初始所有者已经交接或停用的文件包仍可以创建副本，后续操作按当前成员权限执行。

Git 模式继续采用可信团队与仓库访问边界，本机设备身份不是服务账户密码。服务模式的真实账户、密码、会话和集中鉴权已有独立实现，见[服务账户与运行](10-服务账户与运行.md)。

## 桌面文件包入口

Git 初始化可选“从文件包创建”；通过系统文件选择器选取文件包、目录选择器授权父目录，再填写新文件夹。创建完成后明确选择原有成员，保留业务 ID、成员、评论、附件及历史，生成新的副本设备身份，不自动取得所有者权限。

已有空间的“Git 同步 → 离线文件包”提供导入和所有者导出。导入返回当前冲突或受阻记录数量；导出显示本机路径和实际文件大小，明确尚未交给其他成员。导出路径来自系统保存对话框，前端不能提交任意目标路径。已选文件和目录使用不同授权标识；开始前重新检查文件、父目录和空间身份。

本机校验、合并和落位在后台运行。开始前可以取消；已经开始的本机操作继续完成，关闭界面不撤回已保存的数据，正常退出会等待结束。部分导入后出现 Git 关联错误时保留原有错误与重试语义，不能显示为全部回滚。

macOS 原生验收已完成完整往返：首份 7,293 字节文件包创建副本，原文档内容 V2、两位成员、原评论和 137 字节中文附件保留；副本新增评论后导出 8,337 字节回传包，由原空间导入读取。重复导入及无效包拒绝均未改写原文件；关闭重开后只读成员能看到两条评论与原附件，且没有导出及业务写入口。两个副本的附件 SHA-256 与原始文件一致。当前证据在 `/private/tmp/farflow-qa/git-pack/`。
