# 服务正式迁移与账户交接

服务模式已复用共享迁移协议，接通 **服务源 → Git 目标** 和 **本地源 → 服务目标**。结合本地 → Git、[服务 → 本地](17-本地目标接收与离线接续.md)及[Git → 服务／本地](18-Git源交接与冻结确认.md)，六条不同模式的正式交接方向均有实现。客户端向导及完整桌面应用仍未完成。

正式交接保留同一空间和业务 ID；普通复制继续创建新空间 ID。源冻结、目标暂存、源完成、目标激活及取消的总体顺序见 [正式迁移与交接](15-正式迁移与交接.md)。

## 身份与权限

服务源的迁移动作必须由当前已改密、启用的真实账户发起，且该账户映射到当前空间的启用所有者。操作者从会话和历史身份绑定取得，时间从数据库取得，不接受调用者伪造业务操作者或操作时间。

服务目标暂存需要完整、唯一的历史身份 → 真实账户映射，包括放弃分支作者和停用成员。当前发起人必须是映射后的启用空间所有者；服务管理员身份本身不能替代空间所有者。创建用户和普通复制仍按各自已有权限执行。

迁移事件同时保存历史成员 ID、实际账户 ID 和数据库时间。核对时检查事件操作者与绑定一致，并验证该成员在对应历史切点具有所有者权限。历史操作者后来被停用或交接角色，不会改写过去的事件。

服务快照增加可空的 `transfer`，只包含公开计划和阶段，供成员查看只读原因；不会返回控制记录内的待发令牌。完整阶段事件及交接动作限所有者使用。

使用中、冻结中和待激活的服务空间继续保护最后一位有效所有者。已经确认完成交接的只读源不再阻挡原所有者账户停用；它仍不可写，历史身份和事件保留，完整管理员备份也能保存及恢复该退役源。服务管理员不会因此自动取得该空间的业务访问权限，最后一位服务管理员的保护也不受影响。

## 库接口

| 接口 | 行为 |
| --- | --- |
| `Server::prepare_transfer(token, workspace, id, target, backup_destination)` | 所有者先导出完整单空间备份，再在新事务内锁定当前空间、核对当前权限和账户、取得固定历史切点并冻结 |
| `Server::transfer_status(token, workspace)` | 核对控制记录和完整历史后返回当前公开阶段 |
| `Server::transfer_events(token, workspace)` | 所有者读取已核对的阶段事件，不返回令牌 |
| `Server::export_transfer(token, workspace, destination)` | 在受控源阶段导出固定切点和完整字节，相同有效包可重试 |
| `Server::stage_transfer(token, source, bindings)` | 预检正式包及账户映射，原子建立同 ID 的只读服务目标并返回回执 |
| `Server::complete_transfer(token, workspace, receipt)` | 所有者核对回执，提交源完成状态后返回同计划完成凭据；重试不重复事件 |
| `Server::cancel_transfer(token, workspace, transfer)` | 仅在源尚未完成时取消；恢复源业务写入，旧暂存目标不能取得该源实例的完成凭据 |
| `Server::activate_transfer(token, workspace, activation)` | 目标所有者核对计划、令牌及历史，激活后才允许业务写入 |

已有普通复制和正式暂存复用同一安装流程：会话、私有预检副本、原始字节、完整来源、显式身份绑定、成员索引、事务和核对报告均沿用已有实现。正式包不能按普通复制导入；已有不同空间、计划或阶段不能被覆盖。对已激活目标重试原暂存，只核对计划并保留后续新操作。

管理接口已接入[统一正式迁移 CLI](23-正式迁移命令行.md)，服务命令在能够访问数据库和附件目录的管理机器上运行，使用真实会话。未新增允许远端用户任意指定服务文件路径的 HTTP 接口；本地／Git 桌面向导已接入，受控远端上传下载和服务向导待接。准备时的单空间备份不是完整服务账户备份，完整灾备继续使用管理员的 `Server::backup`。

## 数据库屏障

迁移 0006 增加：

| 数据 | 保存内容 |
| --- | --- |
| `ff_workspace_transfer` | 控制记录规范 TEXT、指纹及业务可写标记；待发令牌保存在私有数据库内 |
| `ff_workspace_transfer_events` | 有序阶段事件、实际账户、规范 TEXT 及指纹 |
| 四张表的 `ff_transfer_fence` | 拒绝只读空间的 INSERT、UPDATE、DELETE |
| `ff_transfer_guard` | 统一数据库触发器函数，按原空间和新空间检查屏障 |

屏障覆盖工作空间、源操作、成员索引及身份绑定。新应用入口先核对可写状态，旧服务进程即使没有新入口检查，也会被数据库拒绝新增业务。原始请求重试若可能补写附件，也受新入口只读检查约束。

冻结事务先锁定空间并改变工作空间行版本，再保存冻结控制和事件。冻结前已建立可重复读快照的写事务，也必须在锁定该空间时重试，不能借旧快照绕过新屏障。触发器检查更新前后两个空间，不能把冻结记录移到另一空间逃逸。

启动核对内置函数定义、四条屏障、启用状态及载荷类型；有控制记录的空间读取还检查控制头、指纹、可写标记和最近事件。迁移动作、阶段查询及完整备份进一步核对完整因果历史、全部事件和实际账户绑定。保留事件但缺失控制记录时拒绝读取和业务写入，不当作未迁移的正常空间。

原生身份回填只补真正缺失的绑定，避免重连冻结空间时对已有绑定重复发起 INSERT。停用账户、改密及会话撤销仍是服务级动作；只读屏障不会阻止服务管理员正常管理其他空间和账户。

## 全局停用与交接切点

服务迁往无服务模式时，需要显式保存空间成员的停用事实，不能只依赖服务登录账户的全局停用。准备、冻结中的导出及首次完成前，均核对“空间启用但真实账户停用”的情况。

如果全局停用发生在冻结之后，首次完成会被拒绝。所有者需取消当前计划、在正常空间中明确停用该成员，再以新迁移 ID 取得新切点。旧暂存目标保持只读，新目标保留真实停用状态。

源已完成后，重复取得原凭据不会改写原批准切点。交接后的 Git 或本地空间沿用自己的可信成员边界；服务账户之后的变化不能被承诺为对离线副本的即时集中撤权。

## 事务、恢复与兼容

源冻结、取消、完成、目标暂存及激活均在工作空间锁和共享账户锁保护下提交。写控制、写事件或数据库最终提交失败，整次业务及阶段变更回滚；源不会因失败而变成半冻结状态，完成凭据不会在提交失败时作为成功结果返回。

完整服务备份增加可选控制记录和阶段事件，保留原始历史、客户端请求、真实账户映射及实际字节。恢复会先离线重建完整历史，核对计划切点、角色、令牌摘要、阶段及事件账户绑定，再写入目标；恢复控制在业务与索引安装完成后落位。冻结、暂存、完成及激活状态都不会在恢复时被自动开放写入。取消状态则继续允许正常业务。

早期无控制字段的原生备份仍按默认无迁移记录读取。源会话仍不备份、不恢复，恢复后必须重新登录。历史迁移 ID 在本地和服务中均不能重新用于另一计划；同一未结束请求可以幂等重试。

完整服务恢复和旧源副本仍遵守单一受控源边界：确认原源离线，核对是否已在另一处取消或完成，再恢复相应交接。不能将旧备份恢复出的并行源当作无服务全局锁的替代品。
