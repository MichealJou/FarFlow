# FarFlow 实施与验收计划

实施按依赖推进，正式首版覆盖本地、Git、服务三种模式。阶段样品可以先验证部分能力，但不能将只完成本地的阶段样品作为三模式产品交付。

## 实施阶段

| 阶段 | 内容 | 交付门槛 |
| --- | --- | --- |
| 1 领域与交互定稿 | 业务对象、关系、状态机、初始化、列表与详情、数据格式 | 一条完整业务流程可逐步演示；需求与模式差异无歧义 |
| 2 共享核心与本地闭环 | 共享命令、SQLite、附件、备份；需求到发布 | 真实保存、关闭应用、冷启动重开后数据一致 |
| 3 Git 协作 | 操作协议、索引重建、双副本合并、冲突、文件包 | 离线分头修改、同步、冲突解决及重复导入均可复现 |
| 4 服务协作 | 共享核心的 HTTP 适配、PostgreSQL、身份、权限 | 两个客户端通过真实服务完成业务及并发校验 |
| 5 首版整合 | 三模式界面、迁移、中文搜索、安装包和兼容性 | 三模式验收矩阵全通过，才交付正式首版 |
| 后续增强 | 路线图、甘特、复杂流程、DevOps、治理及 AI | 每项单独明确范围和验收，沿用核心与适配器 |

工期在完成阶段 1、Git 并发验证样品和团队资源确认后估算。Git 的语义冲突、跨模式迁移和桌面兼容性是重点成本，不能按普通增删改查估算。

## 硬性代码质量规则

- 每个公开函数或类都有对应单元测试，覆盖率不低于 80%。
- 每次修改模块后执行相关测试，全绿才算该模块完成。
- 核心模块覆盖边界和失败路径：状态转换、关系约束、版本冲突、持久化、同步和迁移。
- 覆盖率同时检查行、函数和分支；新增公开接口要能映射到测试，不能只靠全局覆盖率掩盖空白模块。
- 不创建未使用模块、工具类、示例代码或空适配器；优先使用标准库和已有成熟能力。
- 新增第三方依赖先说明用途，避免自行实现通用 Git、压缩、加密、数据库或文本协同算法。

## 三模式共用业务验收

以下场景在三种模式分别执行，记录真实界面和持久数据结果：

1. 创建工作空间、产品和项目，建立并关联迭代。
2. 提交原始需求并附图，转成正式需求，保存内容和验收标准。
3. 完成评审、加入计划、拆任务、指派和开始。
4. 修改已批准需求，确认旧版本保留，关联任务收到变更提示。
5. 开发提交完成并交验收，确认未被直接计为已关闭。
6. 创建构建及用例版本，执行测试失败并转 Bug。
7. 修复 Bug 并提交待复测，测试失败重开，再通过并关闭。
8. 产品验收需求，创建发布，核对需求、构建、修复及已知问题。
9. 修改后续需求或用例，确认已发布快照及历史测试结果不变。
10. 完整退出重开、备份恢复到新目录，核对关联及附件哈希。

## Git 专项验收

| 场景 | 预期 |
| --- | --- |
| 两台电脑离线创建不同任务 | 同步后两条都存在，ID 不冲突 |
| 同时评论和上传同一内容附件 | 评论不丢失，附件内容去重且可读取 |
| 同时修改相同字段 | 出现明确冲突，不静默覆盖 |
| 同时修改独立字段 | 仅在业务校验通过后合并 |
| 关闭与重开并发 | 待人工处理，不能凭时间先后决定 |
| 删除与编辑并发 | 保留双方证据，允许明确恢复或保留删除 |
| 调整输入顺序后重建索引 | 相同操作集合得到相同结果及冲突集合 |
| 重复导入同一文件包 | 对象、评论、历史数量不重复增加 |
| 缺少依赖或附件、包损坏 | 提示具体缺口，既有工作空间不被半包替换 |
| 操作已落盘但投影事务中断 | 重开可补齐投影，操作不丢失 |
| Git 推送失败或远端又有更新 | 保留本机变化，可重试，不默认强推 |
| 本机索引丢失 | 从规范数据完整重建，无需他人提供数据库 |
| 迁移期间有未解决冲突 | 阻止正式切换并列出问题 |

## 本地及服务专项验收

本地验证目录不可写、空间不足、附件落位失败、事务回滚、异常退出、升级失败和备份恢复。运行本地及 Git 模式时检查没有启动业务监听端口，也不依赖数据库服务或 Redis。

服务验证不同角色的读取和写入、跨工作空间访问、附件下载、导出、命令重试、版本冲突、连接中断及服务重启。重复命令保持幂等；对象更新和历史写入不能部分成功。

SQLite 和 PostgreSQL 适配运行相同业务契约用例。不能只对本地适配测试后推断服务模式一致。

## 性能及平台目标

首版支持目标为 macOS、Windows、Linux，实际交付分别记录安装、启动、文件选择、附件、中文输入、搜索和重开结果。

性能样本暂定一个工作空间包含 1 万条工作项和 5 万条操作记录，先测列表、筛选、中文搜索及全量索引重建。记录硬件、数据量、冷暖启动和耗时后再确定承诺；Git 历史增长与附件总量另行测量。

## 发布完成条件

需求范围、公开接口测试及覆盖率、核心边界测试、三模式真实操作、双副本同步、备份恢复、迁移和目标平台结果均有可复查记录。开发自验与后续用户验收分别记录。
